# Ultra-Low-Barrier ComfyUI Workflow Integration App (comfy-panel-standalone)

> **Language**: **English** · [简体中文](README.md)

> This document is aimed at **users and redistributors**: what this is, how to install it, how to generate images, and how to troubleshoot problems.
>
> **One-line positioning**: a **self-contained, ready-to-run** local ComfyUI workflow integration app — it ships its own Node backend and browser Web UI, **copying the entire project folder completes the migration**, and it has **zero npm dependencies** (only the Node standard library). No plugin host or external platform is required.

## 0. Why We Call It "Ultra-Low-Barrier"

| Barrier of traditional ComfyUI | How this app removes it |
|---|---|
| You must first install Python, then PyTorch/CUDA, then pip a pile of dependencies | **Not needed**: the portable Node and the ComfyUI portable package are downloaded, extracted, and started by the program itself; the Python environment comes bundled with the ComfyUI portable package |
| You must know how to git clone, how to read errors, how to configure the model directory | **Not needed**: after extracting, just **double-click `start.cmd`** and it starts up, with the browser opening automatically; where models go is arranged automatically by the program according to the ComfyUI portable package's directory conventions |
| You must find models yourself and battle download speeds on domestic networks | Just **pick a tier** in the wizard: the default "minimal tier **5.24 GB**" is exactly the **default image generation model** set (turbo main weights + text encoder + VAE); every component comes with **multiple domestic mirrors**, and if a source makes no progress within 10 seconds it will **switch sources automatically** |
| People who already have ComfyUI / already have models don't want to download again | The wizard supports **specifying an existing local ComfyUI directory** and **importing from an existing local model directory** (**hard link** method, no extra disk usage) |
| You don't know how to write prompts | Built-in **LLM prompt generation** (or switch to an **external API** with one click, such as DeepSeek); a Chinese description is turned directly into positive / negative prompts; there is also a **character index** (40,931 Danbooru character tags + 563 Chinese aliases) and an **artist library** |
| Download progress is invisible and is lost when you switch pages | Jobs are **server-side jobs**: the top bar permanently shows "⏳ Background Jobs" with progress, **speed**, and **remaining time**; switching pages or closing the wizard page does not interrupt them |
| You don't know which domestic mirror works, and you fear it will hang halfway | The Settings page has **mirror speed testing**: for any direct link it **actually downloads 100 MiB** from every candidate source and reports time to first byte and speed; during downloads, **if there is no progress within 10 seconds it switches sources automatically**, so you don't have to watch it yourself |

> In one line: **download finishes → double-click `start.cmd` → follow the wizard for three steps → images come out**.
> The only step that needs network access is "completing the runtime environment" (the ComfyUI portable package + the selected model tier); if you want to be fully offline, copy `runtime\` and `models\` over together.

## 2. Feature Overview

- **Main model selector, automatically pairing three pipelines**: pick a diffusion model in the dropdown and the panel automatically infers which pipeline to use (`Anima 3.8B` / `Anima General` / `Qwen-Image 2.1`) and automatically derives the corresponding **text encoder**, **VAE**, **conditioning nodes**, and sampler defaults.
- **Multiple images generated one by one**: 1–20 images per run, each with an **independent artist tag and independent seed**, written to disk one at a time, abortable at any moment.
- **Reference image img2img**: choose a local image as the base image plus denoise strength (denoise); when the current pipeline does not support it, it is **automatically disabled with the reason explained** and falls back to pure text-to-image.
- **Live preview / VRAM panel**: during generation it shows live sampling preview frames, per-image progress, and elapsed time; the sidebar shows a VRAM usage bar.
- **Four artist modes + favorites + blocklist + custom artists**: 🎲 big random (59,676) / 🎲 small random (first 200) / ★ random favorites / 🔍 specify (including "favorites only" search and the freely entered `@custom artist`).
- **LLM prompt generation**: built-in llama.cpp subprocess + bundled GGUF; after a couple of messages you get positive / negative prompts in a "single code fence" format; in the **three-column Workbench** it sits on the same screen as the generation panel, and the "Prompt Tools" card offers **one-click fill** (written into the panel's React state) or **one-click copy**.
- **Install centre (replaces the wizard page)**: runtime → ComfyUI itself → custom nodes → model weights → artist lists → license notices, all in one run; optionally "existing local ComfyUI directory" to **import via hard link**, saving a full download.
- **Embedded / external dual mode**: embedded mode installs ComfyUI inside the project (`runtime\comfyui`); external mode points at your existing ComfyUI installation directory.
- **One-click start/stop of ComfyUI**: start/stop the ComfyUI subprocess directly from the panel, and view the tail of its log in the UI.
- **Chinese-English bilingual**: the UI language switches instantly and persists; the panel's own copy is handled by the runtime translation layer.
- **Automatic download mirror switching**: official sources first (10 s timeout, or speed continuously below 200 KB/s for over 30 s), then it switches mirrors automatically and **clearly reports** which source it switched to; the start of the job log also prints the **list of candidate sources**, and on failure it gives "source#round: reason" for each one.

### 2.1 Round 2 Additions (Three-in-One Workbench / Character Index / External API / Domestic Sources / Tray)

- **Three-in-one Workbench**: the former "generation / LLM / artists" three separate pages are now **three columns side by side on the same page** (`.wb-gen` / `.wb-llm` / `.wb-art`), each column **independently scrollable and collapsible**; at the top there is a "three columns / two columns / generation only" layout switch (the choice is stored in the browser `localStorage` under `dcp-workbench-layout`), and when the window is narrow it degrades automatically at CSS breakpoints (<1560px collapses the artist column, <1180px drops to a single column). The left navigation is left with only three items: **Workbench / Settings / Wizard**.
- **A larger recommended local model**: a new recommended model catalog `installer/llm-models.json` (7 entries, with measured byte counts and licenses), defaulting to the recommendation of `unsloth/Qwen3.5-9B-GGUF`'s `Qwen3.5-9B-UD-Q4_K_XL.gguf` (**5,966,095,584 B**, Apache-2.0, with a byte-identical mirror on ModelScope); it can be downloaded with one click / set as default inside the "LLM" column.
- **Character index + Chinese aliases + output completion**: at runtime it downloads the MIT-licensed Danbooru character tag index (`danbooru.csv`, **3,518,020 B / 140,782 lines**, of which the character tags with category=4 number **40,931**), paired with **563 built-in Chinese/Japanese aliases** and the user-extensible `data\character-aliases.json`; when a model response is missing canonical character tags, the backend adds them into the positive prompt and **clearly displays** "character tags completed per the character index: …" (explicit notification, not silently altering content).
- **External API (pure chat kernel)**: the "inference source" can be switched to any OpenAI-compatible endpoint (such as `https://api.deepseek.com/v1`, and it also supports a local `llama-server` at `http://127.0.0.1:8199/v1`), doing **pure chat only**: one system prompt (still the original `assets/templates/anima-system-prompt.txt`) + the most recent N conversation turns, with no tools / no retrieval / no inference kernel attached.
- **Domestically usable download sources**: **ModelScope** (`modelscope.cn`) is added as a mirror layer for HuggingFace files (`/resolve/` direct links are rewritten automatically, and `main` also tries `master`); **pasting web page links directly is supported** (HF `/blob/`, ModelScope `/file/view/`, the legacy ModelScope `?Revision=&FilePath=`); the default GitHub proxy list adds `https://ghps.cc/`; the Settings page adds **"one-click fill of preferred domestic sources"**, the ModelScope base URL, the `useModelScope` switch, and the **stall threshold `stallKBs` (default 30 KB/s)**.
- **Console minimization + tray icon**: after the launcher is ready it opens the Web UI automatically → starts the tray assistant as a separate process → **minimizes the console to the taskbar**; the tray right-click menu offers "Open Web UI / Copy access address / Open log folder / Close console and stop backend", and the icon disappears automatically after the backend exits. Adding `-NoTray` turns off the tray and the minimization.

> **9B measured conclusion (filled in at the end of this round)**: the ModelScope download of 5,966,095,584 B completed and the **sha256 matched the remote**; on 8 GB VRAM (with ComfyUI online at the same time) `-ngl 99` put everything on the GPU and it was **ready in 12.3 seconds**; English counting, Chinese prompt generation, and character recognition all worked correctly — asked "Rem's Danbooru character tag", it answered `rem`, and in the full prompt it wrote out `rem_(re:zero)` on its own.
> **At the same time a real problem was hit and fixed**: the first file completed by "resumable download" had **perfectly correct byte count but corrupted content** (the model answered with hundreds of `?` every time). After re-downloading, the sha256 matched and it was normal. Therefore this round adds **sha256** to the recommended catalog, performs streamed verification automatically after a download completes, and on mismatch deletes the file and reports an error, plus a "Verify integrity" button. See appendices I/J of `docs/FULL-REFERENCE.md`.

## 4. Quick Start (Three Steps)

### Step 1: Get the project

Put the entire `<project root>` folder anywhere on the machine (for example `<drive>:\comfy-panel-standalone`).
**There is no npm install step** — the project has zero npm dependencies.

### Step 2: Double-click `start.cmd`

`start.cmd` calls `scripts\start.ps1`, which is responsible for:

1. Deriving the project root from the **script's own location** (so it still works after renaming, changing drives, or copying the whole thing);
2. Finding a Node runtime (portable Node → Node 18+ in PATH → automatically downloading portable Node);
3. Starting the backend and waiting up to 60 seconds until `/app/state` returns 200 (if the port is occupied it tries the next ones — **at most 2 increments since v1.3.0**, after which it fails fast and suggests `DCP_PORT`);
4. Opening the browser automatically;
5. Starting the tray assistant (a separate process) and **minimizing the console to the taskbar** — to exit, **right-click the system tray icon → "Close console and stop backend"** (you can also restore the console from the taskbar and press `Ctrl+C`); the tray icon disappears automatically after the backend exits.
   **Since v1.3.0, exiting also stops the ComfyUI this app started** (only its own instance; a ComfyUI you started yourself is never touched): the tray requests a graceful quit first (`POST /app/quit`), falls back to a forced kill, and re-cleans from the ownership records afterwards; anything still left behind (for example if you killed `node` directly) is cleaned on the next start. See §14's v1.3.0 entry and `docs/HANDOVER.md` §13.2.

> If you don't want the tray / don't want the console minimized: use `pwsh -File .\scripts\start.ps1 -NoTray` (see §4.1).

### Step 3: Open `http://127.0.0.1:8788/` in the browser

By default it lands on **🎛 Workbench** in the left navigation: **generation panel / local LLM / artists in three columns side by side** (see §6), so writing prompts and producing images happen on one screen.
Then go to **🚀 Wizard** in the left navigation and run through the first-run wizard (see §5). Until the wizard has been run, a "Please complete the wizard first" banner appears at the top of the page.

### 4.1 `scripts\start.ps1` Parameters

```powershell
pwsh -File .\scripts\start.ps1                 # Default: read the port from data\settings.json, auto-open browser + tray + minimize console
pwsh -File .\scripts\start.ps1 -Port 8899      # Specify the backend port for this run
pwsh -File .\scripts\start.ps1 -Lan            # Listen in LAN mode for this run (equivalent to turning on the LAN switch on the Settings page)
pwsh -File .\scripts\start.ps1 -NoBrowser      # Do not open the browser automatically
pwsh -File .\scripts\start.ps1 -NoTray         # Do not install the tray icon, and do not minimize the console
pwsh -File .\scripts\start.ps1 -Foreground     # Print backend logs directly to the current console (by default written to logs\server*.log)
```

| Parameter | Effect |
|---|---|
| `-Port <n>` | Specify the backend port. When omitted it reads `listen.port` from `data\settings.json`, and uses `8788` if absent |
| `-Lan` | Listen in LAN mode for this run (`0.0.0.0`); a token is required for access, see §10 |
| `-NoBrowser` | Do not open the browser automatically (server / unattended scenarios) |
| `-NoTray` | **Do not install the tray icon and do not minimize the console** (use when you need to keep watching console output) |
| `-Foreground` | Output backend logs directly to the current console, suitable for diagnosing startup problems (the tray is also not installed in this mode) |

> Exit: **right-click the system tray icon → "Close console and stop backend"**, or restore the console from the taskbar and press `Ctrl+C`, or simply close that window.
> The tray menu also has: Open Web UI (same effect as double-clicking the icon), Copy access address, Open log folder. The tray's own log is at `<project root>\logs\tray.log`.

## 5. First-Run Wizard

Left navigation → **🚀 Wizard**. The UI guides you step by step, and every step shows installed/not-installed status.

### 5.1 Step 1: Choose the run mode

| Mode | Meaning |
|---|---|
| **Embedded mode (embedded)** | This program installs ComfyUI into `<project root>\runtime\comfyui` and starts it with its bundled `python_embeded` |
| **External mode (external)** | Use the ComfyUI directory you **have already installed** (enter the directory → click "Detect" to confirm the layout and weights directory) |

### 5.2 Step 2: Obtain ComfyUI itself (embedded mode only)

The dropdown has five sources:

| Source | Description |
|---|---|
| **Portable (portable)** | Default. It first asks the GitHub Releases API for the current portable package asset name, and on failure tries candidate names in order (`ComfyUI_windows_portable_nvidia.7z` → `_nvidia_cu126.7z` → `ComfyUI_windows_portable.7z`), then automatically extracts and "hoists" the layer after downloading |
| **Archive (archive)** | Specify **an existing local `.7z` archive** and skip the download (the easiest option when offline or when downloads are slow) |
| **Existing directory (dir)** | Point at **an already installed local ComfyUI directory** and import it into the project: the code directory is imported as a whole (skipping `__pycache__` / `.git` / `output` / `temp` / `input` / `user`), and weights are moved with **hard links** (instantaneous on the same volume, automatically falling back to copying across volumes) |
| **Git repository (git)** | `git clone` a specified commit + create a `venv` + install dependencies from a pip mirror (requires system git and Python) |
| **Skip (skip)** | Do nothing (handle it yourself later) |

The same screen also has **"Existing local ComfyUI directory (optional)"**: after filling in an already installed local ComfyUI directory, the wizard will **hard link/copy** already downloaded weights from it to the target location, avoiding repeat downloads — **also useful for offline installation**.

### 5.3 Step 3: Choose model weights

- **Tier buttons**: `minimal` / `standard` / `full`; one click checks all the models of that tier;
- **Per-model checkboxes**: each of the 12 models has a checkbox, and the row shows the filename, GB size, and license marker; ones already in place are labeled "installed";
- The right side shows the **total GB** still to be downloaded this time.

Tier containment (`minimal ⊂ standard ⊂ full`):

| Tier | Meaning | Cumulative GB |
|---|---|---|
| `minimal` | **Default tier**: exactly the panel's default image generation model `anima-turbo-v1.1.safetensors` + its text encoder `qwen_3_06b_base` + `qwen_image_vae` | ≈ **5.24 GB** |
| `standard` | minimal + `Anima-3.8B-v1.1` + `qwen35_4b` + the two official general Anima weights (`anima-base` / `anima-aesthetic`) | ≈ 25.69 GB |
| `full` | All 12 models (plus the full 2.9B / 2.9B-int8 / Qwen-Image 2.1 sets) | ≈ 47.27 GB |

For the complete list see §10.3 or read `installer/models.json` directly.

### 5.4 Steps 4–5: Artist lists and license

- **Artist lists**: copy the two `.txt` files under `assets/artists/` and `NOTICE.md` into `model-notes\` on the ComfyUI side, and the panel can read them (a 59,676-entry big pool + the first 200 entries as a small pool).

### 5.5 Step 6: LLM (skippable)

The wizard only gives a hint here; the actual installation/model switching is done in "🎛 Workbench → LLM column", see §8. **Skipping it does not affect image generation at all.**

### 5.6 Progress and logs

All long jobs uniformly use "job + SSE": the UI has a progress bar and line-by-line logs, and **any failure gives clear wording** — it never fails silently. Each job also leaves a `.log` under `<project root>\logs\jobs\`.

## 6. Workbench and generation panel guide

Left navigation → **🎛 Workbench** (the default page). The Workbench puts three things **side by side on the same page**:

| Column | Content | Description |
|---|---|---|
| Left column `.wb-gen` | generation panel | The model is the master selector; every subsection in this section is about this column |
| Middle column `.wb-llm` | LLM / external API | Write a prompt → "Prompt tools" one-click fill into the left column, see §8 |
| Right column `.wb-art` | artist | favorites / blocklist / search, see §7 |

- Each column **scrolls independently**, and the **▾/▸** button on its title bar can **collapse** that column (giving the space to the other two);
- The "**Layout: three columns / two columns / generation only**" switch at the top stores the choice in the browser's `localStorage` under `dcp-workbench-layout` (a pure UI preference, not written into settings);
- **It degrades automatically when the window is narrow** (pure CSS breakpoints, taking effect immediately when the window is resized): below 1560px the artist column is collapsed, and below 1180px it drops to a single column (in the two-column layout the LLM column is collapsed directly).

### 6.1 Model master selector → automatically derives the trio

**Choose the diffusion model first**, and the pipeline and the other dropdowns change to follow:

| Pipeline | Diffusion model | Text encoder | VAE | Latent space |
|---|---|---|---|---|
| **Anima 3.8B** (v2 bundle) | `Anima-3.8B-v1.1.safetensors` | `qwen_3_06b_base.safetensors` (1024-dim, "native encoder") | `qwen_image_vae.safetensors` | 16 channels |
| **Anima general** | `anima-turbo-v1.1` / `anima-base-v1.0` / `anima-aesthetic-v1.1` / `Anima-2.9B-*` | `qwen_3_06b_base.safetensors` (1024-dim) | `qwen_image_vae.safetensors` | 16 channels |
| **Qwen-Image 2.1** | `qwen_image_2.1_int8_convrot.safetensors` | `qwen3vl_8b_w4a8.safetensors` (4096-dim) | `qwen_image_2.1_vae_bf16.safetensors` | 64 channels |

The basis for derivation is **empirical rules**, not guessing at filenames: the Anima 3.8B route looks at the combo of `Anima38BV2Loader` (that combo is obtained by the node itself mmap-scanning the metadata of `diffusion_models\*.safetensors`), while the other weights go through ComfyUI's own `detect_unet_config` determination (Anima family = `image_model='anima'` → 16 channels), and Qwen-Image 2.1 is recognized by the filename `qwen[-_]?image`.

**There is a hard pre-submit gate**: when the latent channel counts of the model/VAE do not match, or the encoder dimensions do not match, it **does not submit silently**; instead it names the two files and the reason outright. When an image crashes, it also appends a plain-language explanation after ComfyUI's original error (wrong channel count / wrong encoder chosen with `normalized_shape=[4096]`).

**Parameter defaults follow the model**: Anima 3.8B defaults to 40 steps / CFG 6; Anima general defaults to 30 steps / CFG 4; Qwen-Image 2.1 defaults to 25 steps / CFG 1; and weights whose filename contains `turbo` are automatically changed to **CFG 1 / 10 steps**.

### 6.2 Generation parameters

| Control | Description |
|---|---|
| Resolution | Width and height are aligned to multiples of 8, range 64–4096; each of the three pipelines has its own presets (such as Anima 3.8B's 832×1216 portrait and Qwen's 2048×2048 native 2K) |
| Steps | 1–100 (out-of-range values automatically converge) |
| CFG | 0.1–30 |
| Count | **1–20, generated one image at a time**; each image draws its artist and its seed independently |
| Seed | A fixed value or "random seed"; different for each image when there are several |
| Positive / negative prompt | One text box each; a "🧪 Test image" button one-click fills a uniform test prompt (black-and-white spotted puppy + grass) |
| 📋 One-click replace | Reads the system clipboard and, by the `Positive prompt:` / `Negative prompt:` keywords, **automatically distinguishes and replaces** the positive/negative; when the clipboard API is unavailable (no permission or a non-secure context), the UI degrades to an **in-panel paste box** so you can paste and confirm manually |

### 6.3 Reference image (img2img)

- Click **🖼 Choose reference image** to upload a local image (uploaded to ComfyUI's `dsh-panel-ref` directory), and the panel shows a thumbnail;
- **Denoise strength (denoise)** only takes effect when a reference image is used, range 0.05–1.00, default 0.75; while it is in effect the **width/height inputs are automatically ignored**;
- **Automatically disabled when unsupported**: when the current pipeline lacks the `LoadImage` / `VAEEncode` nodes, or no VAE is selected, the description line gives the **specific reason**, that generation **carries no reference image**, and it falls back to pure text-to-image (generation is not blocked);
- Click **✕ Clear** to return to pure text-to-image.

### 6.4 Live preview and VRAM

- During generation it shows the **live sampling preview frame** first, and switches back to the final image written to disk once it finishes;
- The live line shows "image i/n · status · elapsed" and a progress bar;
- With multiple images there is a thumbnail strip below; click a thumbnail to switch the large image, and click the large image to open the original in a new tab;
- The **VRAM / RAM** area shows `VRAM used / total GB` and a usage bar;
- The **Free VRAM** button: unloads models and clears the VRAM cache (during generation it reports "not releasing for now").

### 6.5 On-disk filename contract

Generated images are saved by ComfyUI's `SaveImage`, with `filename_prefix` fixed to:

```
<model folder>\<artist|noartist>_<index>_00001_.png
```

- `<model folder>` = the diffusion model's filename with `.safetensors` removed (for example `anima-turbo-v1.1`);
- `<artist>` = the artist tag used for this generation (with the `@` prefix removed and filesystem-illegal characters removed); **when no artist is injected, `noartist` is written**;
- `<index>` = which image in this batch (starting from 1);
- `00001_` and `.png` are appended by ComfyUI.

> The artist tag shown in the panel is taken from the generation metadata first; when there is no metadata it falls back to being derived from the **on-disk filename**.

## 7. Artist system

### 7.1 Five artist modes ("Off" + four tiers)

| Mode | Candidate pool | Description |

## 8. LLM prompt generation (including external API and character index)

Left navigation → **🎛 Workbench** → **LLM column** (the middle column). You can also choose "generation only" under "Layout" to collapse it.

### 8.1 The default model and its limits (please read this first)

The GGUF bundled with the project is **`Qwen3.5-2B-UD-Q5_K_XL.gguf`** (about 1.4 GB, a 2B quantized tier). This is a **speed-first** choice:

- Its **ability to follow instructions is limited**: it may not dutifully write just one code fence, and it may stuff negative tags into the positive section, spam a long string of near-synonyms in the negative, or write a verbose chain-of-thought;
- Therefore the program applies **format normalization** to the output: it takes only the **first** code fence, **de-duplicates by comma** within the same line, applies **redundancy truncation** to an overlong "word soup" (more than 120 tags or 800 characters), truncates negative opening words mistakenly placed in the positive, and removes tags that also appear in the positive from the negative;
- **Whenever content is rewritten, the UI and the logs both state it clearly** (for example "omitted N pieces of redundant content…", "the answer hit the length cap and was truncated"), and it **never silently alters content**; when the positive/negative structure cannot be recognized, the model output is returned as-is, without fabricating content.

> **Want higher quality?** Switch to a larger GGUF in "LLM → **Model management**" (using "Add local path" or "Download model"), then "Set as default" and restart the service. The larger the model, the slower it is, but the more stable its format compliance.

### 8.5 Chat, context and "new conversation"

- The **context message count** defaults to **5** and can be adjusted to **0–20** in "Settings → LLM" (0 = no history at all); the page's title line shows the currently effective value;
- Only "system prompt + the most recent N messages" is sent to the model, and the **system prompt does not count toward N**;
- **"New session" (new conversation) = start a fresh chat, keep the history** (since v1.2.1): it allocates a new session id, clears the on-screen messages and the reasoning block, and cancels an in-progress streaming answer; the previous session stays in `data\llm\sessions.json` and can be reopened from the "Chat history (kept forever)" card at any time. With the local provider it also calls llama.cpp's slot erasure API to clear the inference cache (the external API has no such concept);
- **History is kept forever** (since v1.2.1): refreshing, switching tabs and restarting all resume the last chat; the "Chat history (kept forever)" card lists every session, one click loads a whole conversation, and only its Delete button (two-step confirm) really deletes one (deleting the current one falls back to the most recently updated one). Each session keeps at most `keepMessages` messages locally (default 40, adjustable **2–2000** in Settings; it only affects on-screen review and copying, **not how many are sent to the model**);
- The sampling parameters are tuned for generating "short, structured" prompts (low temperature, tightened truncation, DRY to suppress degeneration), and the **chain-of-thought is turned off** (`enable_thinking: false`); the answer length has a hard cap (512 tokens by default), so a small model cannot eat up the whole context writing a several-thousand-token chain-of-thought;
- If the model outputs only reasoning and the body is empty, the UI **returns the reasoning as the answer with a clear explanation** (since v1.2.1 the reasoning text has already been streamed into the "Reasoning" block, so it is not sent twice), and never silently gives an empty answer.

### 8.6 System prompt

Clicking "Show" on the "System prompt" card displays the currently effective original text — it is **fixed** to come from `<project root>\assets\templates\anima-system-prompt.txt`, and the program **does not append any other identity or tool description**. To read or change it, read or edit that file directly (restart the backend after editing).

### 8.7 Prompt tools: one-click fill + one-click copy

Below the reply is the "**Prompt tools (parsed result → panel)**" card, which first parses the **last** assistant reply into positive/negative, previews it in read-only boxes, and then:

| Location | Button | Behavior |
|---|---|---|
| Positive read-only box | **📋 Copy** / **⬅ Fill** | Copies the parsed positive to the clipboard / writes it into the positive box of the generation panel |
| Negative read-only box | **📋 Copy** / **⬅ Fill** | Same as above, for the negative |
| Card footer | **Fill both** | Fills both sections at once |
| Card footer | **📋 Copy positive + negative** | Copies both sections in the format `Positive prompt: …` blank line `Negative prompt: …` |
| Card footer | **📋 Copy the whole reply** | Copies the model's entire reply text |
| Character search result row | **📋 Copy** | Copies that Danbooru tag (see §8.8) |

- Parsing rules: it preferentially takes the **last** fenced block that contains both `Positive prompt:` and `Negative prompt:`; when no fence is found, the whole text is the fallback; **"Fill" is grayed out** when nothing can be parsed (with a reason given), and **"Copy" only needs an answer** (changed in v1.2.1 — the old build also gated copying on a successful parse, so a reply without the expected fence left both buttons grey: the reported "generated content cannot be copied").
- **Copy** uses `navigator.clipboard` first, and falls back to a hidden `textarea` + `execCommand` when it is unavailable; if both paths fail it reports "Copy failed".
- **Fill** goes through the panel-exposed `window.__DCP_PANEL_API__.setPrompts()` (a real React `setState`), so the prompt really takes part in generation rather than only changing the DOM display; after filling it automatically switches to the generation column and reports how many sections were filled.

### 8.7.1 Reasoning view (external API, since v1.2.1)

When the reasoning tier is not `off` (or the upstream returns `reasoning_content` on its own), the reasoning text is streamed **as its own frames** and rendered as a "**🧠 Reasoning (N chars)**" block *before* the answer body:

| Element | Behavior |
|---|---|
| Block title | Shows the accumulated character count; while streaming it says "Model is thinking…" |
| **Show / Hide** | Display only; expanded by default |
| **Copy reasoning** | Copies the whole reasoning text (separate from the answer, no cross-contamination) |
| Body | Monospace, gray, scrollable; shown even when the answer is empty so you never wait in the dark |

The backend only falls back to returning the reasoning as the answer when the body is empty, and says so explicitly.

> **A real defect fixed in this round**: when a reply **ended with a closing ```**, the old `parseFence()` treated "the empty string after the end" as another fence, and since parsing takes the **last** fence → positive/negative were always empty → all the "Fill / Copy" buttons were grayed out. The fix: only accept fences **with content**; only when the number of backticks is **odd** (genuinely unclosed) and the tail has content is the tail treated as a candidate.

### 8.8 Character index and Chinese aliases (character recognition fallback)

**The conclusion first (with measured evidence)**: **none of** the text-to-text models that run on 8 GB of VRAM **can reliably** translate a name like "蕾姆" into a canonical Danbooru character tag —

- The only NL→Danbooru model (BooruNL-0.8B) explicitly states in its model card that it "does not output character / artist tags";
- The only Danbooru tag model (DanTagGen) is **tag in → tag out**, and requires someone to supply the characters field first;
- The weights explicitly fine-tuned with DanbooruTags are **27B**, and even the smallest quantization will not fit into 8 GB.

So the approach in this version is "**a larger general-purpose model (9B) + a deterministic character index as a fallback + Chinese aliases**", and **not** a claim that some model can recognize the vast majority of characters.

| Component | Location | Description |
|---|---|---|
| **character index** | `<project root>\data\characters\danbooru.csv` | Downloads the MIT-licensed tagcomplete `danbooru.csv` at runtime: **3,518,020 B / 140,782 lines**, of which the character tags with `category=4` number **40,931** (with post counts); the index is **lazily loaded** and ready to use right after installation |
| **Built-in Chinese aliases** | In the code (`server/characters.js`) | **563 entries** (mainstream works such as Re:Zero / FGO / Touhou / VOCALOID / Genshin Impact / Honkai: Star Rail / Zenless Zone Zero / Wuthering Waves / Arknights / Blue Archive / Uma Musume / hololive / Naruto / One Piece / Dragon Ball / P5), for example `蕾姆 → rem_(re:zero)`, `初音未来 → hatsune_miku`, `甘雨 → ganyu_(genshin_impact)`; **every single entry was checked one by one against `danbooru.csv`** (583 candidates → 20 deleted → 563/563 exact hits), and at runtime it self-checks once more and reports the number of misses in the logs/status API |
| **User aliases** | `<project root>\data\character-aliases.json` | Extensible; in the "character index" card, just fill in "Chinese/Japanese name → the corresponding Danbooru tag name" |

**How to use it**: in the "character index (Danbooru character tag index)" card in the "LLM" column, click **"Download/update index"** (about 3.5 MB, going through the unified download strategy), then search with "**Search characters (Chinese or English both work)**"; result rows show the tag and post count, and **📋 Copy** gets you the canonical tag directly.

**Output completion (explicitly announced, not silently changing content)**: when the model's answer is missing canonical character tags, the backend **adds them into the positive prompt** from the index and returns a `charactersAdded` frame, and the UI shows a system notice "**Character tags completed from the character index: …**". Completion is only appended when the positive section (or the whole reply) can be recognized, and characters that already appeared in the reply are not added again.

**How false hits are handled**: common Chinese words such as "时 / 天天 / 天使 / 真理 / 琴 / 小美 / 白露 / 悠悠 / 陈 / 玛丽 / 吉尔 / 忧" **never go into the alias table** (to avoid reading an ordinary sentence as a character); if a false hit still occurs, you can turn off **"Character index completion"** in "Settings → local LLM" (`llm.characterRepair`, on by default) — once it is off, the program **does not modify** the model output at all.

### 8.9 External API (inference source = external API, **default**)

> **Reasoning tier (four tiers)**: the "Reasoning tier" dropdown on the Settings page, or the same dropdown on the chat page — **off** (thinking off, default, fastest and most stable) /
> **low** / **high** / **max**. Measured with DeepSeek: off uses 0 thinking tokens and produces the body within 1 s; max thinks for over a thousand characters first (measured 3.2 s,
> 430 thinking progress frames), with a longer body but slower and more expensive. The "Test connection" self-check reports the current tier back to you.

> **Context stays local only (default)**: the UI keeps the whole history, and every message and the whole conversation can be **one-click copied**,
> but by default **history is not sent to the model** — each turn sends only the current sentence, so that the previous turn's wording does not bias this one.
> When you need multi-turn context, just check "Send context to the model" on the chat page / Settings page (it will then send the most recent N messages according to the "context message count").


> **The default is the external API**: it works out of the box, uses no VRAM, and requires no several-GB weight download first. Just fill in a Key;
> if you do not have a Key yet, you can switch back to **local model** in "Settings → LLM → inference source" (a 4B model is already installed on this machine).

**Verified by measurement with DeepSeek (`deepseek-flash`)**: on the Settings page click the **DeepSeek** preset → paste the API Key →
click "Test connection" and you should see `ok · <elapsed>ms · deepseek-flash · N models · "可以"`; "Fetch model list" fills the server's models into the dropdown.
Command-line equivalent verification: `POST /app/llm/api/test`, `POST /app/llm/api/models`, `POST /app/llm/chat` (over SSE).

**The pitfall with thinking models (the core of this round's fix)**: by default `deepseek-flash` spends all of `max_tokens` on thinking, leaving the body empty —
it shows up as "the API clearly returns 200, yet the UI has nothing". This version turns thinking **off** by default and leaves enough `max_tokens` (4096 by default);
when you do want thinking, just change "Thinking mode" on the Settings page to "leave it to the server default".



In the "Settings → LLM" group there is an **"inference source"**: **local model (llama.cpp)** or **external API (OpenAI-compatible)**. When the external option is selected you **do not** need to install the llama.cpp runtime, nor download any GGUF.

| Field | Description |
|---|---|
| **API address (baseUrl)** | For example `https://api.deepseek.com/v1`; a local `http://127.0.0.1:8199/v1` is also supported (using `llama-server` as an OpenAI-compatible endpoint) |
| **API Key** | Written only to `<project root>\data\settings.json` (already gitignored), and **never goes into logs or delivery documents**; the page uses a password field and does not echo it back |
| **Model name** | The model id required by the server, for example `deepseek-chat` |
| **Temperature / per-call cap** | The sampling temperature and the token cap for a single answer |

- **Connectivity self-check**: click "**Test connection**" (`POST /app/llm/api/test`) — it first tries `/models` (supported by most services), then sends a very short chat (`max_tokens: 8`, non-streaming), and returns the elapsed time in milliseconds and the model name; on failure it gives the status code and the reason.
- **Chat**: goes through `/chat/completions` **streaming**, converted into this program's front-end SSE. It does **pure chat only**: one system prompt (still the **original text** of `assets/templates/anima-system-prompt.txt`) + the most recent N messages, with **no tools, no retrieval, no reasoning kernel attached**.
- **Common error mapping**: `401/403` → the API Key is invalid or lacks permission; `404` → the baseUrl or the model name is wrong (most services require the `/v1` level); `429` → rate limiting was triggered.
- The external path also performs output normalization and **character tag completion**, and the returned frames carry `provider: "api"`; the local path carries `provider: "local"`.

### 9.1 About the two items "minimize to tray after launch / close button behavior"

These two items exist in the **plugin build** and are **deliberately not provided** in this standalone build. The reason is written in the "Window" card on the Settings page:

> The standalone build is a pure browser page (a backend process + static pages) with **no tray process**, so "automatically minimize to tray after launch" and "close button behavior" do not apply and are therefore not provided. To exit, close the launcher window or press `Ctrl+C` in the window.

**Be careful to distinguish the two "trays"**: the above refers to the **browser page side** (the page itself cannot manage windows, so no fake toggles are provided); whereas the **launcher side** (`scripts\start.ps1`) now really does bring up a **system tray icon** in a separate process and minimizes the console — that is launcher behavior, disabled with `-NoTray`, unrelated to the Settings page; see §4.1 and F6 in `FEATURES.md`.

### 9.2 LAN access

After enabling "allow LAN access", the backend listens on `0.0.0.0` and automatically generates a **token** (displayed on the Settings page). Other devices on the LAN must carry the token to gain access:

```
http://<local IP>:8788/?token=<token>
```

or the `X-DCP-Token` request header. The "LAN address" line in the startup log already includes the token, so you can use it directly. **No verification is performed when the token is off / LAN is not enabled.**

> **The local machine is unaffected by the token (v1.1.0 fix)**: the token is for **other devices on the LAN**; requests from the loopback address (the local browser / launcher health probe) are always allowed through.
> This is crucial: the old implementation demanded a token from every source, so after enabling LAN **even the local page's own API calls all returned 401** —
> the Settings page would be replaced by the shell with "backend API unavailable", so the token could never be seen; moreover the launcher `scripts\start.ps1` uses
> `http://127.0.0.1:<port>/app/state` for its health probe without a token, so once the LAN toggle had been saved, **the next double-click on `start.cmd` would wait the full 60 seconds, report "the backend was not ready within 60 seconds", and kill the backend**.
> Now: after saving, the token is displayed on the Settings page immediately (no page refresh needed), the local machine works as usual, and other devices still must carry `?token=` (or `X-DCP-Token`).

## 11. Frequently Asked Questions (FAQ)

### 1) The web page will not open / the backend did not start

- Confirm it was started via `start.cmd` or `pwsh -File .\scripts\start.ps1`, and **use the address printed in the startup log** (when a port is occupied the backend tries the next ones — **at most 2 increments since v1.3.0** — and the actual port is **no longer written back** into `data\settings.json`; read it from the top-level `port` of `/app/state`, the startup log's "打开: `http://127.0.0.1:<port>/`" line, or `logs\server.log`).
- If the page you are looking at is not the address the service is on (e.g. the port drifted while your old tab stayed open), the top bar shows a **"Service address …"** badge telling you where to go, and a disconnect produces one actionable notice with a "copy address" button — reopen that address.
- The launcher prints "the backend was not ready within 60 seconds" together with the last few lines of output; you can also look at `<project root>\logs\server-console.out.log` and `logs\server-console.err.log`.
- The first run needs a network connection to download the portable Node; with no network and no Node 18+ installed it will fail, and you can follow the prompts in `scripts\bootstrap.ps1` to place `node.exe` into `runtime\node\` manually.
- Use `-Foreground` to see the backend log directly in the console.

### 2) It shows "ComfyUI offline"

- Click the "**Start ComfyUI**" button on the panel and wait for it to become ready (up to 180 seconds; the panel polls `/system_stats`; a cold start is slow and the log is at `logs/comfyui.log`).
- In external mode, first confirm the directory under "Settings → ComfyUI" is correct, then click "Detect" to see whether the layout, `main.py` and `python` were all found.
- If it still fails, look at `<project root>\logs\comfyui.log` (also viewable in the panel/wizard).

### 3) The model dropdown is empty

- ComfyUI must **already be installed and running** before the panel will query its node list; an empty dropdown while offline is normal.
- Confirm the weights have been downloaded into ComfyUI's `models\diffusion_models\` (and `text_encoders\`, `vae\`). Use "Settings → Self-check" or the wizard's model list to see the "installed" marker.
- The `comfy-embedded-missing` notice in the self-check means embedded mode has not installed the core yet; go back to the wizard and run through it once.

### 4) `VAEDecode` reports a channel-count error during generation

This is a **mismatch between the diffusion model's latent space channel count and the VAE** (measured on this machine: the Anima series is 16 channels, Qwen-Image 2.1 is 64 channels). After the raw error the panel appends a plain-language hint.

**What to do**: switch to the VAE that matches the same pipeline (Anima series → `qwen_image_vae.safetensors`; Qwen-Image 2.1 → `qwen_image_2.1_vae_bf16.safetensors`). Normally the panel's **pre-submit gate** stops this combination one step earlier and names both files.

### 5) It reports `normalized_shape=[4096]` / the wrong encoder was selected

This means the **text encoder is wrong**: `[4096]` is the dimension that the Qwen-Image 2.1 text projection requires, but what was actually fed in was 1024-dimensional.

**What to do**:
- Anima 3.8B / Anima general → for "native encoder" select **`qwen_3_06b_base.safetensors`** (1024-dimensional);
- Qwen-Image 2.1 → for "text encoder" select **`qwen3vl_8b_w4a8.safetensors`** (4096-dimensional).

### 6) Clicking "Start" does nothing

- Look at the tail of `<project root>\logs\comfyui.log` — both the panel and the wizard have a log viewer.
- If the log says "no usable Python interpreter found", embedded mode is missing `python_embeded`: go back to the wizard and reinstall using the "portable build" (or an "existing directory" import brings `python_embeded` along with it).
- If ComfyUI is in fact already running (but you did not start it through the panel), "Stop" will try to end the process listening on that port.

### 7) Downloads are very slow / keep failing

- The program automatically switches mirrors and **clearly reports** which source it switched to. Since round 7 the decision rules are two, and both are intuitive:
  - **No normal download start within 10 seconds** (the connection was established but fewer than 64 KiB of data arrived) → switch to the next source immediately;
  - **No new bytes received for 15 consecutive seconds** (the download is stuck mid-way) → switch to the next source immediately;
  - A "persistently slow" competition rule is also retained: an early candidate is switched away as soon as its **average speed over the whole window (default 30 s) is below 200 KB/s**, while the last candidate is not cut off for being "slow" (only stalling is checked), so that a file that could finish is not killed when every source is slow.
  - **All of these thresholds can be adjusted in "Settings → Download source"** (download start deadline / interruption criterion / slow threshold / slow window / stall threshold).
- **Not sure which source works? Test the speed first**: "Settings → Download source → Mirror speed test", paste any direct link (by default it is the minimal-tier main weights), choose 100 MiB and click "Start speed test" — it downloads **one segment from each candidate source** over the real download path and lists time to first byte, actual speed and verdict. The speed test does not write to disk.
- Default tiers for each component (measured in round 7):
  | Component | Default source order |
  |---|---|
  | Model weights (HuggingFace family) | ModelScope (`resolve/master`) → aifasthub → hf-api.gitee.com → ai.gitcode.com → hf-mirror |
  | Node portable runtime | Tsinghua TUNA → official nodejs.org → Huawei Cloud → cdn.npmmirror → registry.npmmirror |
  | Character index `danbooru.csv` | jsDelivr (fastly / gcore) → raw.githubusercontent → gh-proxy / ghfast |
  | GitHub Release (ComfyUI portable package / llama.cpp / 7-Zip) | gh-proxy.com → **down.npee.cn** (`?<original link>` form) → ghproxy.net → ghfast.top |
  | 7-Zip | GitHub `ip7z/7zip` (via gh-proxy, measured 1.8 MB/s) → official 7-zip.org (measured only 17–25 KB/s) → 7-Zip already installed on the system |
  | pip (installing dependencies in git mode) | Tsinghua PyPI → Alibaba Cloud PyPI |
- Downloads support resumable retry; after repeated failures it lists **the failure reason of every source** rather than just saying "it failed".
- If it is truly slow you can download manually and then: for the ComfyUI core use the wizard's "archive" option to point at a local `.7z`; for models, install them into an existing ComfyUI directory on this machine and import them with the wizard's hard link (set "import from an existing local model directory").
- **The reality of GitHub-family resources (stated honestly)**: in 2026-09 more than 20 GitHub proxies were measured on this machine, and **only two are fast sources** — `gh-proxy.com` (230 MB/15 s ≈ 15 MB/s) and `down.npee.cn` (`?<original link>` form, 4.07–24.92 MB/s, official v0.37.0 assets 4/4 passed); `ghproxy.net` / `ghfast.top` do return data but are rate-limited to 0.10–0.37 MB/s; `ghps.cc` is 404 site-wide; the rest have dead DNS / expired certificates / 403 / 429. The program also has several additional fallback paths for the ComfyUI portable package and llama.cpp (hash-verified official older-version mirrors, third-party builds on hf-mirror, git clone mode, local archives, importing an existing external directory).

### 9) LLM fails to start / insufficient VRAM

- **Insufficient VRAM**: click the **CPU build** in "LLM → Install runtime" to reinstall; or switch to a smaller GGUF.
- If it reports missing CUDA runtime libraries, the CUDA build installation flow automatically fetches the cudart package too; if that still fails, fall back to the CPU build.

### 10) After changing computers / drive letters, external mode stops working

External mode records **absolute paths**, so after copying to another machine they may point nowhere. At startup the "self-check" reports:

> The external ComfyUI directory does not exist (most likely the path became invalid after copying everything to another computer/drive letter)

**What to do**: open "Settings → ComfyUI" and point it at the ComfyUI directory on this machine again, or switch to "embedded mode" and let the wizard install it. **All other data (settings, favorites, blocklist, LLM sessions) travels with the project folder and is unaffected.**

### 11) After startup the page says "please complete the wizard first"

The wizard record (`data\setup.json`) does not yet contain `completed`. You can click the "Wizard" button on the banner to run through it; if you only want external mode, choose "external mode" in step 1 of the wizard + fill in the directory + finish once detection passes (you can leave every model unchecked and download them later as needed from the generation panel).

### 12) Generation is slow / VRAM blew up (OOM)

With 8 GB of VRAM, large batches (for example 20 images at 1024²) easily OOM. **What to do**: reduce the number of images or the resolution; click "Free VRAM" to clear the cache; for the Anima series you can switch to an int8 quantized tier such as `Anima-2.9B-preview-v1_int8_convrot.safetensors`.

### 13) I want to use my phone / LAN access

Turn on "Settings → Listen address → **Allow LAN access**" and save: the backend switches to listening on `0.0.0.0` and automatically generates a **token**. Then open this in the browser on your phone/another computer:

```
http://<local IP>:8788/?token=<token>
```

- The token is shown in "Settings → Listen address", and the "LAN address" line in the startup log **already carries the token**, so you can copy it directly;
- Both ends must be on the **same LAN** (the same Wi-Fi/subnet), and Windows Firewall will prompt the first time — you need to **allow** the program to access private networks;
- If the phone browser cannot open it, check first: firewall blocking, the IP having changed (DHCP), and whether `?token=` is missing from the address.

### 14) With 8 GB of VRAM I want to run the 9B from the recommended catalog — will it run?

The 9B in the recommended catalog is `Qwen3.5-9B-UD-Q4_K_XL` (**5,966,095,584 B ≈ 5.56 GiB** of weights). With 8 GB of VRAM it **fits the weights but leaves very little headroom for the KV cache**; try these in order:

1. First **shut down ComfyUI to free VRAM** (generation and the local LLM fighting over VRAM is the most common cause of failure on 8 GB machines);
2. Lower `llm.gpuLayers` (`-ngl`) in `data\settings.json` (for example to 20), or set it to 0 to run purely on CPU;
3. Switch to a more frugal tier: `Qwen3.5-9B-Q4_K_M` (5,680,522,464 B) or `Qwen3-8B-Q4_K_M` (5,027,784,512 B);
4. If that still does not work, click the **CPU build** in "LLM → Install runtime".

> **Stated honestly**: this version only achieves "catalog registration + one-click download available"; **the download-complete and load-and-run verification for the 9B has not been completed** (see "Appendix: round 2 change measurements" H in `docs/FULL-REFERENCE.md`).

### 15) What to do when the external API reports 401 / 404

- **401 / 403**: the API Key is invalid or lacks permission — paste the Key again in "Settings → LLM" (the page uses a password field and does not echo it; the Key is only written to `<project root>\data\settings.json`, which is gitignored and never enters the logs).
- **404**: the `baseUrl` or model name is wrong. The vast majority of services need the `/v1` level included, for example `https://api.deepseek.com/v1`; when using the local `llama-server` as the endpoint it is `http://127.0.0.1:8199/v1`.
- **429**: rate limiting was triggered, try again later.
- First self-check with "**Test connection**" on the Settings page: it tries `/models` first, then sends a very short conversation; the response carries the status code, elapsed time and error body, so you can fix it accordingly.

### 16) Character names are recognized inaccurately (for example "Rem" is not translated into a canonical character tag)

**The conclusion first**: the text-to-text models that run in 8 GB of VRAM **all cannot do this reliably** — the only NL→Danbooru model (BooruNL-0.8B) has a model card that explicitly states "does not output character/artist tags"; the only Danbooru tag model (DanTagGen) is tag in, tag out; the weights explicitly fine-tuned with DanbooruTags are **27B**, which will not fit in 8 GB even at the smallest quantization. This version therefore uses "**a larger general-purpose model + a deterministic character index as a fallback + Chinese aliases**". Practical approaches:

1. **Add a Chinese alias (most effective)**: in the "Workbench → LLM → Character index" card fill in "Chinese/Japanese name → the corresponding Danbooru tag name" and save; it is written to `<project root>\data\character-aliases.json` (user aliases override built-in entries with the same name).
2. **Switch to a larger model**: in "Recommended models" click "Download" for the 9B and "Set as default"; using the **index + a larger model** together works best.
3. **Confirm the index is installed**: click "Download/update index" (about 3.5 MB); the card shows "index ready / 40,931 character entries".
4. **See whether completion happened**: a system notice "**character tags completed from the character index: …**" appears in the UI — this is an explicit notification, not a silent content change; if this notice does not appear, no character name was parsed this time.
5. You can also search directly: enter a name in "Search characters (Chinese or English)", click **📋 Copy** on the result row to get the canonical tag, then fill it into the prompt by hand.

### 17) The tray icon is gone

- Look at `<project root>\logs\tray.log` first: it contains "tray ready: Url=… BackendPid=…" or "backend exited, tray closing", and a failed WinForms load also records a reason.
- **The icon disappearing automatically after the backend exits is by design** (to avoid leaving a ghost icon that cannot be clicked); just start the project again.
- Windows 11 hides tray icons in the "hidden icons" area by default; click the `^` on the taskbar to expand it, and you can also drag the icon out to pin it.
- If startup used **`-NoTray`** or **`-Foreground`** there will be **no** tray icon (this is intentional).
- If `scripts\tray.ps1` is missing or WinForms is unavailable, the launcher prints a **warning and keeps the console visible**; in that case press `Ctrl+C` to exit.

### 18) What to do when downloads keep failing

1. Open "Settings → Download source" and click **"One-click fill preferred China sources"**: it sets the HuggingFace mirror to `hf-mirror.com`, enables ModelScope, fills in the four GitHub proxies (`gh-proxy.com` / `ghproxy.net` / `ghfast.top` / `ghps.cc`) in one go, and sets the stall threshold to 30 KB/s.
2. Look at the **first line** of the task log: "`<filename> has N candidate sources: official source → hf-mirror → modelscope → …`" — that tells you exactly which sources the program tried; on failure the end of the log lists "`source#round: reason`" one by one.
3. **ModelScope does not have every file**: the `modelscope` field in `installer/llm-models.json` marks whether it does; when the repository does not exist it 404s immediately and automatically jumps to the next candidate.
4. The slow-speed decision uses the **average speed over the window**, not an instantaneous value, and **the last candidate is judged only by the stall threshold** (as long as it is still moving, it will be downloaded to completion) — this avoids killing a file that could have finished when "all sources are slow".
5. Requests always carry `User-Agent` and `Range` headers (which also gives resumable download support); after connecting, a source is declared dead and switched only if not a single byte moves for 20–60 seconds.
6. If it really will not download, download manually: use the wizard's "archive" / "existing directory" for the ComfyUI core, and "add local path" or the wizard's "existing local ComfyUI directory" for models.

### 19) The 9B model never finishes downloading — is it broken?

No. The 9B weights are a single file on the order of **5.56 GiB**, and **dropping the connection mid-way is the norm** on networks in China (measured on this machine, this round saw several interruptions: official source timeouts, mirror window average speeds of only 1–2 MB/s). The program already: ① tries candidate sources one by one, ② retries each source for 2 rounds, ③ resumes downloads (`.part` + `Range`), ④ honestly lists the reason for each source on failure. **It reports errors clearly and never fails silently**; rerunning the same task continues from the breakpoint. You can also click "One-click fill preferred China sources" and retry, or download manually and then "add local path".
