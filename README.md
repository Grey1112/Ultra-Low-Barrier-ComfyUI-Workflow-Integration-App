# 超低门槛 ComfyUI 工作流集成应用（comfy-panel-standalone）

> **语言 / Language**：**简体中文** · [English](README.en.md)

> 本文档面向**使用者与二次分发者**：说明这是什么、怎么装起来、怎么生图、出问题怎么查。
>
> **一句话定位**：一个**独立运行、开箱即用**的本地 ComfyUI 工作流集成应用 —— 自带 Node 后端与浏览器 Web UI，**拷贝整个项目文件夹即完成迁移**，**零 npm 依赖**（只用 Node 标准库），不需要任何插件宿主或外部平台。

## 0. 为什么说"超低门槛"

| 传统 ComfyUI 的门槛 | 这个应用怎么把它拿掉 |
|---|---|
| 要先装 Python、再装 PyTorch/CUDA、再 pip 一堆依赖 | **不需要**：便携 Node 与 ComfyUI 便携包由程序自己下载、自己解压、自己起；Python 环境用 ComfyUI 便携包自带的 |
| 要会 git clone、会看报错、会配模型目录 | **不用**：解压后**双击 `start.cmd`** 就起来，浏览器自动打开；模型放哪由程序按 ComfyUI 便携包的目录约定自动摆好 |
| 要自己找模型、自己在国内网络下和下载速度搏斗 | 向导里**选一个档位**即可：默认「最小档 **5.24 GB**」正好是**默认生图模型**那一套（turbo 主权重 + 编码器 + VAE）；每个组件都配了**多个国内镜像**，某个源 10 秒内下不动会**自动换源** |
| 已有 ComfyUI / 已有模型的人不想重复下载 | 向导支持**指定本机已有 ComfyUI 目录**与**从本机已有模型目录导入**（**硬链接**方式，不额外占盘） |
| 提示词不会写 | 内置**本地 LLM 提示词生成**（或一键切**外接 API**，如 DeepSeek），中文描述直接变成正/负向提示词；还有**角色词表**（40,931 条 Danbooru 角色 tag + 563 条中文别名）与**画师库** |
| 下载进度看不见、切页面就丢 | 任务是**服务端任务**：顶栏常驻「⏳ 后台任务」显示进度、**速度**与**剩余时间**，切页面/关向导页都不中断 |
| 不知道国内哪个镜像能下、怕下到一半卡死 | 设置页有**镜像测速**：对任意直链把每个候选来源**真下 100 MiB**，报首字节与速度；下载时**10 秒内没有进展就自动换源**，不需要你自己盯着 |

> 一句话：**下载完成 → 双击 `start.cmd` → 跟着向导点三步 → 出图**。
> 需要联网的只有"补齐运行环境"这一步（ComfyUI 便携包 + 选中的模型档位）；想完全离线就把 `runtime\` 与 `models\` 一起拷过去。

## 2. 特性总览

- **模型主选择器，自动配对三条管线**：下拉里选一个扩散模型，面板自动反推该走的管线（`Anima 3.8B` / `Anima 通用` / `Qwen-Image 2.1`），并自动派生对应的**文本编码器**、**VAE** 与**条件节点**、采样器默认值。
- **多张逐张生成**：一次可出 1–20 张，每张**独立画师 tag、独立种子**，逐张落盘、随时中止。
- **参考图 img2img**：选一张本地图片作底图 + 重绘幅度（denoise）；当前管线不支持时**自动无效并说明原因**，回落到纯文生图。
- **实时预览 / 显存面板**：生成过程中显示采样实时预览帧、逐张进度与耗时；侧栏显示显存占用条。
- **画师四档 + 收藏 + 黑名单 + 自定义画师**：🎲 大随机（59,676）/ 🎲 小随机（前 200）/ ★ 随机收藏 / 🔍 指定（含"仅收藏"检索与自由输入的 `@自定义画师`）。
- **本地 LLM 提示词生成**：内置 llama.cpp 子进程 + 预置 GGUF，聊两句就得到「单代码围栏」格式的正/负向提示词；在**工作台三栏**里与生图面板同屏，「提示词工具」卡片可**一键填入**（写进面板 React state）或**一键复制**。
- **首次运行向导**：运行时 → ComfyUI 本体 → 自定义节点 → 模型权重 → 画师清单 → 许可声明，一步跑完；可选「本地已有 ComfyUI 目录」**用硬链接导入**，省一次全量下载。
- **内嵌 / 外接双模式**：内嵌模式把 ComfyUI 装在项目内（`runtime\comfyui`）；外接模式指向你已有的 ComfyUI 安装目录。
- **一键启停 ComfyUI**：面板上直接启动/停止 ComfyUI 子进程，并可在界面里查看它的日志尾巴。
- **中英双语**：界面语言即时切换并持久化；面板本身的文案由运行时翻译层处理。
- **下载镜像自动切换**：官方源优先（超时 10 s 或速度持续低于 200 KB/s 超 30 s），自动切镜像并**明确提示**切到了哪个源；任务日志开头还会打印**候选来源列表**，失败时逐条给出「来源#轮次: 原因」。

### 2.1 第二轮新增（三合一工作台 / 角色词表 / 外接 API / 国内源 / 托盘）

- **三合一工作台**：原来「生图 / 本地 LLM / 画师」是三个独立页面，现在**同一页三栏并排**（`.wb-gen` / `.wb-llm` / `.wb-art`），每栏**独立滚动、可折叠**；顶部有「三栏 / 两栏 / 仅生图」布局切换（选择存在浏览器 `localStorage` 的 `dcp-workbench-layout`），窗口窄时按 CSS 断点自动降级（<1560px 收起画师栏，<1180px 降到单列）。左侧导航只剩 **工作台 / 设置 / 向导** 三项。
- **更大的推荐本地模型**：新增推荐模型目录 `installer/llm-models.json`（7 条，含实测字节数与许可），默认推荐 `unsloth/Qwen3.5-9B-GGUF` 的 `Qwen3.5-9B-UD-Q4_K_XL.gguf`（**5,966,095,584 B**，Apache-2.0，ModelScope 有同字节镜像）；在「本地 LLM」栏内可一键下载 / 设为默认。
- **角色词表 + 中文别名 + 输出补全**：运行时下载 MIT 许可的 Danbooru 角色 tag 索引（`danbooru.csv`，**3,518,020 B / 140,782 行**，其中 category=4 的角色 tag **40,931** 条），配 **563 条内置中文/日文别名**与用户可扩展的 `data\character-aliases.json`；模型回答里缺规范角色 tag 时后端补进正向提示词，并**明确显示**「已按角色词表补全角色 tag：…」（显式告知，不是静默改内容）。
- **外接 API（纯聊天内核）**：「推理来源」可切到任意 OpenAI 兼容接口（如 `https://api.deepseek.com/v1`，也支持本机 `http://127.0.0.1:8199/v1` 的 `llama-server`），**只做纯聊天**：一段系统提示词（仍是 `assets/templates/anima-system-prompt.txt` 原文）+ 最近 N 条对话，不挂工具 / 不挂检索 / 不挂推理内核。
- **国内可用下载源**：新增 **ModelScope**（`modelscope.cn`）作为 HuggingFace 文件的镜像层（`/resolve/` 直链自动改写，`main` 会同时试 `master`）；**支持直接粘贴网页链接**（HF `/blob/`、ModelScope `/file/view/`、ModelScope 旧式 `?Revision=&FilePath=`）；GitHub 代理默认列表增加 `https://ghps.cc/`；设置页新增 **「一键填入国内优选源」**、ModelScope 基地址、`useModelScope` 开关与**停滞阈值 `stallKBs`（默认 30 KB/s）**。
- **控制台最小化 + 托盘图标**：启动器就绪后自动打开 Web UI → 拉起独立进程的托盘助手 → **把控制台最小化到任务栏**；托盘右键菜单可「打开 Web UI / 复制访问地址 / 打开日志文件夹 / 关闭控制台并停止后端」，后端退出后图标自动消失。加 `-NoTray` 可关掉托盘与最小化。

> **9B 实测结论（本轮末补齐）**：ModelScope 下完 5,966,095,584 B 且 **sha256 与远端一致**；在 8 GB 显存（ComfyUI 同时在线）下 `-ngl 99` 全量上卡、**12.3 秒就绪**，英文计数、中文提示词生成、角色识别三题都正常 —— 问它"蕾姆的 Danbooru 角色 tag"，它答 `rem`，整段提示词里自己就写出了 `rem_(re:zero)`。
> **同时踩到并修掉一个真问题**：第一次"断点续传"补出来的文件**字节数完全正确、内容却是坏的**（模型每次回答都是几百个 `?`）。重下后 sha256 一致即正常。因此本轮给推荐目录补上 **sha256**，下载完成后自动流式校验、对不上就删文件并报错，另加「校验完整性」按钮。详见 `docs/FULL-REFERENCE.md` 附录 I/J。

## 3. 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | **Windows 10/11 x64** |
| Node.js | **18 或更高**；但**不需要预装** —— 项目启动时优先使用自带的便携 Node（`runtime\node`），缺失时由 `scripts\bootstrap.ps1` 自动下载（约 v22.14.0 x64）；也可手动装 Node 18+ 并放进 PATH |
| PowerShell | Windows 自带的 PowerShell 5.1 即可（`start.cmd` 会优先找 `pwsh`，找不到就用 `powershell`） |
| GPU | **建议 NVIDIA GPU，显存 ≥ 8 GB**。8 GB 下建议降低张数或分辨率；`Anima-2.9B-preview-v1_int8_convrot` 是 8 GB 显存友好档 |
| 磁盘（ComfyUI 本体） | 官方 Windows 便携包为**数 GB 量级**，解压后占用更大 |
| 磁盘（模型权重） | 按 `installer/models.json` 的档位：**minimal ≈ 5.24 GB**、**standard ≈ 25.69 GB**、**full ≈ 47.27 GB**（均按十进制 GB 汇总 `bytes` 字段；含 ComfyUI 本体后请再留余量） |
| 磁盘（本地 LLM） | **可为零**：默认走外接 API，不装本地模型也能用。本机现装 `Qwen3.5-4B-UD-Q4_K_XL.gguf`（**2,912,109,728 B ≈ 2.71 GiB**）；推荐目录里的 9B（5,966,095,584 B）与 2B（1,466,687,744 B）**只给链接，不再自动下载** |
| 磁盘（角色词表） | 约 **3.5 MB**（`data\characters\danbooru.csv`），首次用角色功能时下载 |
| 网络 | 首次运行需要联网（下 ComfyUI、模型、画师清单、可选 LLM 运行时）。国内网络会走镜像，见 §12 |

## 4. 快速开始（三步）

### 第 1 步：获取项目

把整个 `<项目根>` 文件夹放到本机任意位置（例如 `<盘符>:\comfy-panel-standalone`）。
**没有 npm install 这一步** —— 项目零 npm 依赖。

### 第 2 步：双击 `start.cmd`

`start.cmd` 会调用 `scripts\start.ps1`，它负责：

1. 以**脚本自身位置**推导项目根（所以改名、换盘符、整体拷贝后依然可用）；
2. 找 Node 运行时（便携 Node → PATH 里的 Node 18+ → 自动下载便携 Node）；
3. 拉起后端，最多等 60 秒直到 `/app/state` 返回 200（端口被占用时会自动往后试）；
4. 自动打开浏览器；
5. 拉起托盘助手（独立进程），并**把控制台最小化到任务栏** —— 要退出就**右键系统托盘图标 → 「关闭控制台并停止后端」**（也可以从任务栏把控制台还原出来按 `Ctrl+C`）；后端退出后托盘图标会自动消失。

> 不想用托盘 / 不想让控制台最小化：用 `pwsh -File .\scripts\start.ps1 -NoTray`（见 §4.1）。

### 第 3 步：浏览器打开 `http://127.0.0.1:8788/`

默认落在左侧导航的 **🎛 工作台**：**生图面板 / 本地 LLM / 画师三栏并排**（见 §6），写提示词与出图在同一屏完成。
再去左侧导航的 **🚀 向导** 走一遍首次运行向导（见 §5）。向导没跑完时，页面顶部会有一条「请先完成向导」的横幅。

### 4.1 `scripts\start.ps1` 参数

```powershell
pwsh -File .\scripts\start.ps1                 # 默认：读 data\settings.json 的端口，自动开浏览器 + 托盘 + 最小化控制台
pwsh -File .\scripts\start.ps1 -Port 8899      # 指定本次后端端口
pwsh -File .\scripts\start.ps1 -Lan            # 本次以局域网模式监听（等价于打开设置页的局域网开关）
pwsh -File .\scripts\start.ps1 -NoBrowser      # 不自动打开浏览器
pwsh -File .\scripts\start.ps1 -NoTray         # 不装托盘图标，也不最小化控制台
pwsh -File .\scripts\start.ps1 -Foreground     # 后端日志直接打到当前控制台（默认写 logs\server*.log）
```

| 参数 | 作用 |
|---|---|
| `-Port <n>` | 指定后端端口。不传时读 `data\settings.json` 的 `listen.port`，没有则用 `8788` |
| `-Lan` | 本次以局域网模式监听（`0.0.0.0`），需要令牌才能访问，见 §10 |
| `-NoBrowser` | 不自动打开浏览器（服务器/无人值守场景） |
| `-NoTray` | **不装托盘图标、也不最小化控制台**（需要一直盯着控制台输出时用） |
| `-Foreground` | 把后端日志直接输出到当前控制台，适合排查启动问题（此模式下也不装托盘） |

> 退出：**右键系统托盘图标 → 「关闭控制台并停止后端」**，或把控制台从任务栏还原后按 `Ctrl+C`，或直接关闭该窗口。
> 托盘菜单还有：打开 Web UI（双击图标同效）、复制访问地址、打开日志文件夹。托盘自己的日志在 `<项目根>\logs\tray.log`。

## 5. 首次运行向导

左侧导航 → **🚀 向导**。界面按步骤引导，每一步都能看到已装/未装状态。

### 5.1 第 1 步：选择运行模式

| 模式 | 含义 |
|---|---|
| **内置模式（embedded）** | 由本程序把 ComfyUI 装进 `<项目根>\runtime\comfyui`，并用它自带的 `python_embeded` 启动 |
| **外接模式（external）** | 使用你**已经装好的** ComfyUI 目录（填目录 → 点「检测」确认布局与权重目录） |

### 5.2 第 2 步：获取 ComfyUI 本体（仅内置模式）

下拉里有五种来源：

| 来源 | 说明 |
|---|---|
| **便携版（portable）** | 默认。先问 GitHub Releases API 拿当前的便携包资产名，失败则按候选名依次尝试（`ComfyUI_windows_portable_nvidia.7z` → `_nvidia_cu126.7z` → `ComfyUI_windows_portable.7z`），下载后自动解压并"提层" |
| **压缩包（archive）** | 指定**本地已有的 `.7z` 归档**，跳过下载（离线或下载慢时最省事） |
| **已有目录（dir）** | 指向**本机已装好的 ComfyUI 目录**，把它导入项目内：代码目录整体导入（跳过 `__pycache__` / `.git` / `output` / `temp` / `input` / `user`），并用**硬链接**搬运权重（同卷瞬时、跨卷自动回落为复制） |
| **Git 仓库（git）** | `git clone` 指定 commit + 建 `venv` + 用 pip 镜像装依赖（需要系统 git 与 Python） |
| **跳过（skip）** | 什么都不做（稍后自己处理） |

同一屏还有 **「本地已有 ComfyUI 目录（可选）」**：填上本机已装好的 ComfyUI 目录后，向导会从里面**硬链接/复制**已下载的权重到目标位置，避免重复下载 —— **离线安装也有用**。

### 5.3 第 3 步：选择模型权重

- **档位按钮**：`minimal` / `standard` / `full`，点一下就把对应档位的模型全部勾上；
- **逐模型勾选**：12 个模型每个都有勾选框，行内显示文件名、GB 数、许可标识，已就绪的会标注"已安装"；
- 右侧显示本次仍需下载的**合计 GB**。

档位包含关系（`minimal ⊂ standard ⊂ full`）：

## 6. 工作台与生图面板使用说明

左侧导航 → **🎛 工作台**（默认页）。工作台把三件事**并排放在同一页**：

| 栏 | 内容 | 说明 |
|---|---|---|
| 左栏 `.wb-gen` | 生图面板 | 模型即主选择器；本节各小节讲的都是这一栏 |
| 中栏 `.wb-llm` | 本地 LLM / 外接 API | 写提示词 → 「提示词工具」一键填入左栏，见 §8 |
| 右栏 `.wb-art` | 画师 | 收藏 / 黑名单 / 检索，见 §7 |

- 每栏**独立滚动**，标题条上的 **▾/▸** 按钮可**折叠**该栏（把空间让给其它两栏）；
- 顶部「**布局：三栏 / 两栏 / 仅生图**」切换，选择记在浏览器 `localStorage` 的 `dcp-workbench-layout`（纯界面偏好，不写进设置）；
- **窗口窄时自动降级**（纯 CSS 断点，缩放窗口即时生效）：< 1560px 收起画师栏，< 1180px 降到单列（两栏布局下会直接收起 LLM 栏）。

### 6.1 模型主选择器 → 自动派生三件套

**先选扩散模型**，管线与其它下拉会自动跟着变：

| 管线 | 扩散模型 | 文本编码器 | VAE | 潜空间 |
|---|---|---|---|---|
| **Anima 3.8B**（v2 bundle） | `Anima-3.8B-v1.1.safetensors` | `qwen_3_06b_base.safetensors`（1024 维，"原生编码器"） | `qwen_image_vae.safetensors` | 16 通道 |
| **Anima 通用** | `anima-turbo-v1.1` / `anima-base-v1.0` / `anima-aesthetic-v1.1` / `Anima-2.9B-*` | `qwen_3_06b_base.safetensors`（1024 维） | `qwen_image_vae.safetensors` | 16 通道 |
| **Qwen-Image 2.1** | `qwen_image_2.1_int8_convrot.safetensors` | `qwen3vl_8b_w4a8.safetensors`（4096 维） | `qwen_image_2.1_vae_bf16.safetensors` | 64 通道 |

派生的依据是**实证规则**，不是猜文件名：Anima 3.8B 路线看 `Anima38BV2Loader` 的 combo（该 combo 是节点自己 mmap 扫 `diffusion_models\*.safetensors` 的 metadata 得来的），其余权重走 ComfyUI 自己的 `detect_unet_config` 判定（Anima 系 = `image_model='anima'` → 16 通道），Qwen-Image 2.1 按文件名 `qwen[-_]?image` 识别。

**提交前有硬闸门**：模型/VAE 的潜空间通道数不匹配、或编码器维度不匹配时，**不会静默提交**，而是直接点名两个文件与原因。崩图时也会在 ComfyUI 的原始报错后面追加一段人话解释（通道数错误 / `normalized_shape=[4096]` 编码器选错）。

**参数默认值跟着模型走**：Anima 3.8B 默认 40 步 / CFG 6；Anima 通用默认 30 步 / CFG 4；Qwen-Image 2.1 默认 25 步 / CFG 1；而文件名含 `turbo` 的权重自动改为 **CFG 1 / 10 步**。

### 6.2 出图参数

| 控件 | 说明 |
|---|---|
| 分辨率 | 宽高按 8 的倍数对齐，范围 64–4096；三条管线各有预设（如 Anima 3.8B 的 832×1216 竖版、Qwen 的 2048×2048 原生 2K） |
| 步数 | 1–100（越界自动收敛） |
| CFG | 0.1–30 |
| 张数 | **1–20，逐张生成**；每张独立取画师、独立取种子 |
| 种子 | 固定值或"随机种子"；多张时逐张不同 |
| 正向 / 负向提示词 | 各一个文本框；有「🧪 测试图」一键填入统一测试提示词（黑白斑点小狗 + 草地） |
| 📋 一键替换 | 读系统剪贴板，按 `Positive prompt:` / `Negative prompt:` 关键词**自动区分并替换**正/负向；剪贴板 API 不可用（无权限或非安全上下文）时，界面会降级出一个**面板内粘贴框**让你手动粘贴确认 |

### 6.3 参考图（img2img）

- 点 **🖼 选择参考图** 上传一张本地图片（上传到 ComfyUI 的 `dsh-panel-ref` 目录），面板会显示缩略图；
- **重绘幅度（denoise）** 仅在使用参考图时生效，范围 0.05–1.00，默认 0.75；生效时**宽/高输入自动忽略**；
- **不支持时自动无效**：当前管线缺少 `LoadImage` / `VAEEncode` 节点、或没选 VAE 时，说明行会给出**具体原因**，本次生成**不携带参考图**，回落为纯文生图（不拦截生成）；
- 点 **✕ 清除** 回到纯文生图。

### 6.4 实时预览与显存

- 生成中优先显示**采样实时预览帧**，跑完切回落盘的最终图；
- 实时行显示「第 i/n 张 · 状态 · 已耗时」与进度条；
- 多张时下方有缩略图条，点缩略图切换大图，点大图在新标签页打开原图；
- **显存 / 内存** 区显示 `显存 已用 / 总量 GB` 与占用条；
- **释放显存** 按钮：卸载模型并清空显存缓存（生成中会提示"暂不释放"）。

### 6.5 落盘命名契约

生成的图片由 ComfyUI 的 `SaveImage` 保存，`filename_prefix` 固定为：

```
<模型文件夹>\<画师|noartist>_<序号>_00001_.png
```

- `<模型文件夹>` = 扩散模型文件名去掉 `.safetensors`（例如 `anima-turbo-v1.1`）；
- `<画师>` = 本次使用的画师 tag（去掉 `@` 前缀、去掉文件名非法字符）；**没有注入画师时写 `noartist`**；
- `<序号>` = 本次批次里的第几张（从 1 开始）；
- `00001_` 与 `.png` 由 ComfyUI 追加。

> 面板显示的画师 tag 优先取自生成元数据；没有元数据时回落到**落盘文件名**反推。

## 7. 画师体系

### 7.1 五种画师模式（"关闭" + 四档）

| 模式 | 候选池 | 说明 |
|---|---|---|
| **关闭** | — | 不注入画师 tag，文件按 `noartist_序号` 记 |
| **🎲 大随机（全部 59,676 位画师）** | `assets/artists/Anima2B_Artist_Index_59k.txt` | 每次生成**逐张**随机取一位 |

### 7.2 图上的三个按钮

| 按钮 | 行为 |

| **🎯 选为画师** | 把画师模式切到**指定画师**并固定为这一位（等同在搜索列表里点选） |
| **🚫 拉黑 / 🚫 取消拉黑** | 写入/移出黑名单（收藏与拉黑**互斥**） |

### 7.3 黑名单与自定义画师

- **黑名单在"所有随机档"剔除**：大随机、小随机、随机收藏三档的候选池都会过滤掉黑名单里的 tag。若收藏里的画师被全部拉黑，会提示"收藏里的画师都被拉黑了，本次不注入画师"。
- **指定模式仍可搜到被拉黑的画师**，但会标注「已拉黑」，可手动取消拉黑。
- **自定义画师**：在指定模式下直接输入名字即可用 —— 默认格式规范化为 `@名字`（下划线转空格、只保留 Danbooru tag 允许字符），**不做清单校验**，所以清单里没有的画师也能用。
- **收藏与黑名单互斥、后执行覆盖**：同一 tag 加入一个列表时，会自动从另一个列表移除（由服务端保证）。
- **旧数据一键导入**：如果你以前用过插件版，收藏存在浏览器 `localStorage` 的 `dcp-artist-favs`。打开独立版时外壳会**自动检测并一次性迁移**到服务端；「工作台 → 画师栏」里也有一个「从浏览器旧数据导入」按钮可手动触发。

### 7.4 画师栏（工作台右栏）

四张卡片：**收藏**（chip 列表，✕ 移除）、**黑名单**（chip 列表 + "收藏与黑名单互斥"说明）、**搜索**（关键词 + 范围切换 `全部` / `高频` / `收藏`，结果行有 ⭐ 与 🚫 按钮）、**从浏览器旧数据导入**。`assets/artists/` 里的两份清单随项目携带，不必依赖 ComfyUI 目录。

## 8. 本地 LLM 提示词生成（含外接 API 与角色词表）

左侧导航 → **🎛 工作台** → **本地 LLM 栏**（中栏）。也可以在「布局」里选「仅生图」把它收起来。

### 8.1 默认模型与它的边界（请务必先读）

随项目预置的 GGUF 是 **`Qwen3.5-2B-UD-Q5_K_XL.gguf`**（约 1.4 GB，2B 量化档）。这是一个**速度优先**的选择：

- 它**遵循指令的能力有限**：不一定老老实实只写一个代码围栏，可能把负向 tag 塞进正向段、在负向里刷一长串近义词、或者写出啰嗦的思维链；
- 因此程序会对输出做**格式规范化**：只取**第一个**代码围栏、同一行内**按逗号去重**、对超长的"词汤"做**冗余截断**（超过 120 个 tag 或 800 字符）、把误放进正向的负向起手词截断、并把同时出现在正向的 tag 从负向里剔除；
- **凡是改写了内容，界面与日志都会明确说明**（例如"已省略 N 处冗余内容…"、"回答触达长度上限被截断"），**绝不静默篡改**；识别不出正负向结构时，原样返回模型输出，不伪造内容。

> **想要更高质量？** 在「本地 LLM → **模型管理**」里换成更大的 GGUF（用「添加本地路径」或「下载模型」），再「设为默认」并重启服务即可。模型越大越慢，但遵循格式的稳定性越好。

### 8.2 运行时安装（llama.cpp）

右侧「安装运行时」卡片有三个按钮：

| 按钮 | 行为 |
|---|---|
| **自动**（推荐） | 探测本机是否有 NVIDIA GPU（跑 `nvidia-smi -L`）：有就用 **CUDA 版**，没有就用 **CPU 版** |
| **CUDA 版** | 强制装 CUDA 版（**需要 NVIDIA GPU**）；CUDA 版若缺运行库会自动补下 cudart 包 |
| **CPU 版** | 强制装 CPU 版（慢，但不需要 NVIDIA GPU） |

装完会跑一次 `llama-server --version` 自检，并显示运行时版本与判定出的来源（`cuda` / `cpu` / `none`）。

**CUDA 版安装失败会自动回落到 CPU 版重试**；两级都失败时给出明确错误（常见原因：CUDA 运行库缺失或显存不足），文案里会提示你改装 CPU 版。

### 8.3 模型管理

| 操作 | 说明 |
|---|---|
| **推荐模型（一键下载）** | 见下方「推荐模型目录」；一键下载 + 设为默认 |
| **添加本地路径** | 指定一个 `.gguf` 文件；可选 `link`（同卷用**硬链接**，跨卷自动回落为复制）或 `copy` |
| **下载模型** | 填 URL + 文件名，走统一下载策略（官方源 → 镜像），有进度、有明确报错；**可以直接粘贴网页链接**（HF 的 `/blob/`、ModelScope 的 `/file/view/` 都会被规范成直链） |
| **设为默认** | 设为默认模型；未显式设置时，列表里第一个可用模型会自动成为默认 |
| **移除模型** | 弹确认框；移除默认模型后会自动切到剩下的第一个 |
| 列表信息 | 文件名、大小、来源（预置 / 已添加 / 已下载）、是否默认、是否 abliterated |

模型文件统一放在 `<项目根>\models\llm\`。

**推荐模型目录**（`installer\llm-models.json`，7 条，字节数与许可都实测核对过；`modelscope` 字段标明该文件在 ModelScope 有没有同字节镜像）：

| 文件 | 字节数 | 许可 | 说明 |
|---|---|---|---|
| `Qwen3.5-9B-UD-Q4_K_XL.gguf` | **5,966,095,584** | Apache-2.0 | **默认推荐**（★）：同族 9B，中文理解与常识明显更好；ModelScope 有镜像；**已实测 8 GB 显存可跑（全量上卡、12.3 s 就绪）** |
| `Qwen3.5-9B-Q4_K_M.gguf` | 5,680,522,464 | Apache-2.0 | 标准 Q4_K_M，显存紧张时优先选它 |
| `Qwen3.5-9B-UD-Q5_K_XL.gguf` | 6,743,680,224 | Apache-2.0 | 更高精度，8 GB 显存偏紧 |
| `Qwen3-8B-Q4_K_M.gguf` | 5,027,784,512 | Apache-2.0 | 上一代 8B 备选，显存最宽裕 |
| `BooruNL-0.8B-Q6_K.gguf` | 629,743,872 | Apache-2.0 | 专做「自然语言 → Danbooru **外观** tag」，模型卡明确写**不输出角色/画师 tag** |
| `ggml-model-Q6_K.gguf`（DanTagGen-delta-rev2） | 323,077,792 | CC-BY-SA-4.0 | 真 Danbooru tag 模型，但是「tag 进 → tag 出」 |
| `mmproj-F16.gguf` | 918,166,080 | Apache-2.0 | 多模态投影文件（可选），**本版未接入 UI** |

> **关于 9B 的如实说明**：已完成 **下载 → sha256 校验 → 加载 → 推理** 全链路实测（8 GB 显存、`-ngl 99`、12.3 s 就绪；角色问题答 `rem`）。需要注意两点：① 上表字节数是**每个文件的完整大小**，下载后会自动核对 sha256；② 本机网络下官方源（huggingface.co）仍然不通，实际是走 hf-mirror / ModelScope，某些第三方仓库（例如 `cooperdk/BooruNL-0.8B`）可能三处都拿不到——那就如实报失败。8 GB 显存下的取舍见 FAQ 第 14 条。

### 8.4 abliterated（溶解版）搜索

「搜索模型」框会经 **HF 镜像**检索 `abliterated` / `uncensored` / `heretic` 类 GGUF，结果按仓库展示（含下载量、许可、文件列表），每个文件都有「下载」按钮。

**如果镜像上确实没有**，程序会**如实告诉你**：*"上游可能确实未发布「溶解版（abliterated）」权重 —— 本程序不会伪造或改名充数"*，并建议你改用「模型管理 → 从本地路径添加」指定自己已有的 GGUF。搜索不可达时也会如实提示。

### 8.5 对话、上下文与"新开对话"

- **上下文条数**默认 **5**，可在「设置 → 本地 LLM」调到 **0–20**（0 = 完全不带历史）；页面标题行会显示当前生效值；
- 送给模型的只有「系统提示词 + 最近 N 条对话」，**系统提示词不计入 N**；
- **「新建会话」（新开对话）= 彻底清空**：删除服务端该会话的上下文、关闭 prompt 缓存，并调用 llama.cpp 的 slot 擦除接口清掉推理缓存，同时取消正在进行的流式回答；
- 采样参数是为"短小、结构化"的提示词生成调过的（低温、收紧截断、DRY 抑制退化），并**关闭思维链**（`enable_thinking: false`）；回答长度有硬上限（默认 512 token），避免小模型写几千 token 的思维链把上下文吃光；
- 若模型只输出了思考内容、正文为空，界面会**原样返回思考内容并明确说明**，不会静默给空回答。

### 8.6 系统提示词

「系统提示词」卡片点「显示」可查看当前生效的原文 —— 它**固定**取自 `<项目根>\assets\templates\anima-system-prompt.txt`，程序**不会追加任何其它身份或工具说明**。想看/想改就直接看/改这个文件（改完重启后端）。

### 8.7 提示词工具：一键填入 + 一键复制

回复下方是「**提示词工具（解析结果 → 面板）**」卡片，先把**最后一条**助手回复解析成正/负向，再用只读框预览，然后：

| 位置 | 按钮 | 行为 |
|---|---|---|
| 正向只读框 | **📋 复制** / **⬅ 填入** | 把解析出的正向复制到剪贴板 / 写进生图面板的正向框 |
| 负向只读框 | **📋 复制** / **⬅ 填入** | 同上，负向 |
| 卡片底部 | **填正负** | 两段一起填 |
| 卡片底部 | **📋 复制正+负** | 按 `Positive prompt: …` 空行 `Negative prompt: …` 的格式复制两段 |
| 卡片底部 | **📋 复制整段回复** | 复制模型的整段回复原文 |
| 角色检索结果行 | **📋 复制** | 复制该条 Danbooru tag（见 §8.8） |

- 解析规则：优先取**最后一个**同时含 `Positive prompt:` 与 `Negative prompt:` 的围栏块；取不到围栏时整段文本兜底；解析不出内容时**按钮置灰**并给出原因，不会乱填。
- **复制**优先用 `navigator.clipboard`，不可用时回落隐藏 `textarea` + `execCommand`；两路都失败会提示「复制失败」。
- **填入**走面板暴露的 `window.__DCP_PANEL_API__.setPrompts()`（真正的 React `setState`），所以提示词会真的参与生成，而不是只改 DOM 显示；填入后自动切到生图栏并提示已填入几段。

> **本轮修掉的一个真实缺陷**：旧版 `parseFence()` 在回复**以闭合的 ``` 结尾**时，会把"结尾之后的空串"也当成一个围栏，而解析取的是**最后一个**围栏 → 正/负向永远为空 → 「填入 / 复制」按钮全部置灰。修法：只收**有内容**的围栏；只有反引号数量为**奇数**（确实未闭合）且尾巴有内容时，才把尾巴当候选。

### 8.8 角色词表与中文别名（角色识别兜底）

**先说结论（有实测依据）**：8 GB 显存能跑的文生文模型**都不能可靠地**把「蕾姆」这类名字翻成 Danbooru 规范角色 tag ——

- 唯一的 NL→Danbooru 模型（BooruNL-0.8B）在模型卡里明确写「不输出角色 / 画师 tag」；
- 唯一的 Danbooru tag 模型（DanTagGen）是 **tag 进 → tag 出**，要先有人给出 characters 字段；
- 明确用 DanbooruTags 微调的权重是 **27B**，最小量化也放不进 8 GB。

所以本版的做法是「**更大的通用模型（9B）+ 确定性角色词表兜底 + 中文别名**」，而**不是**宣称某个模型能认出绝大部分角色。

| 组成 | 落位 | 说明 |
|---|---|---|
| **角色词表** | `<项目根>\data\characters\danbooru.csv` | 运行时下载 MIT 许可的 tagcomplete `danbooru.csv`：**3,518,020 B / 140,782 行**，其中 `category=4` 的角色 tag **40,931** 条（带 post 计数）；**懒加载**索引，装完即用 |
| **内置中文别名** | 代码内（`server/characters.js`） | **563 条**（Re:Zero / FGO / 东方 / VOCALOID / 原神 / 星穹铁道 / 绝区零 / 鸣潮 / 明日方舟 / Blue Archive / 赛马娘 / hololive / 火影 / 海贼 / 龙珠 / P5 等主流作品），例如 `蕾姆 → rem_(re:zero)`、`初音未来 → hatsune_miku`、`甘雨 → ganyu_(genshin_impact)`；**每一条都用 `danbooru.csv` 逐条核对过**（583 条候选 → 删 20 条 → 563/563 精确命中），运行时还会再自检一次并在日志/状态接口里报出未命中条数 |
| **用户别名** | `<项目根>\data\character-aliases.json` | 可扩展；在「角色词表」卡片里填「中文/日文名 → 对应 Danbooru tag 名」即可 |

**怎么用**：在「本地 LLM」栏的「角色词表（Danbooru 角色 tag 索引）」卡片里点 **「下载/更新词表」**（约 3.5 MB，走统一下载策略），再用「**搜角色（中英均可）**」检索；结果行显示 tag 与 post 计数，点 **📋 复制** 直接拿到规范 tag。

**输出补全（显式告知，不是静默改内容）**：模型回答里缺规范角色 tag 时，后端按词表**补进正向提示词**，并回一帧 `charactersAdded`，界面显示一条系统提示「**已按角色词表补全角色 tag：…**」。补全只在能识别出正向段（或整段回复）时追加，且已在回复里出现过的角色不会重复补。

**误命中怎么处理**：「时 / 天天 / 天使 / 真理 / 琴 / 小美 / 白露 / 悠悠 / 陈 / 玛丽 / 吉尔 / 忧」这类**常用中文词一律不进别名表**（避免把普通句子读成角色）；万一仍有误命中，可在「设置 → 本地 LLM」里关掉 **「角色词表补全」**（`llm.characterRepair`，默认开）——关掉后程序**完全不改**模型输出。

### 8.9 外接 API（推理来源 = 外接 API，**默认**）

> **推理挡位（四挡）**：设置页「推理挡位」或对话页同一个下拉 —— **off**（关思考，默认，最快最稳）/
> **low** / **high** / **max**。DeepSeek 实测：off 思考 0 token、1 s 内出正文；max 会先思考上千字（实测 3.2 s、
> 430 个思考进度帧），正文更长但更慢更贵。自检「测试连接」会把当前挡位回报出来。

> **上下文只留在本地（默认）**：界面保留整段历史、每条消息和整段对话都能**一键复制**，
> 但**默认不把历史发给模型** —— 每轮只发当前这一句，避免上一轮的措辞把这一轮带偏。
> 需要多轮上下文时，勾选对话页/设置页的「把上下文发给模型」即可（那时会按「上下文条数」发送最近 N 条）。


> **默认就是外接 API**：开箱即用、不占显存、不必先下几 GB 权重。填一个 Key 即可；
> 若暂时没有 Key，可在「设置 → 本地 LLM → 推理来源」切回**本地模型**（本机已装 4B）。

**用 DeepSeek 实测通过（`deepseek-flash`）**：设置页点 **DeepSeek** 预设 → 粘贴 API Key →
点「测试连接」应看到 `ok · <耗时>ms · deepseek-flash · N models · "可以"`；「获取模型列表」会把服务端模型灌进下拉框。
命令行等价验证：`POST /app/llm/api/test`、`POST /app/llm/api/models`、`POST /app/llm/chat`（走 SSE）。

**思考型模型的坑（本轮修复的核心）**：`deepseek-flash` 默认会把 `max_tokens` 全用在思考上，正文为空 ——
表现为"接口明明返回 200，界面却什么都没有"。本版默认把思考**关掉**并留足 `max_tokens`（默认 4096），
需要思考时在设置页把「思考模式」改成"交给服务端默认"即可。



「设置 → 本地 LLM」分组里有 **「推理来源」**：**本地模型（llama.cpp）** 或 **外接 API（OpenAI 兼容）**。选外接时**不需要**装 llama.cpp 运行时，也不需要下载任何 GGUF。

| 字段 | 说明 |
|---|---|
| **API 地址（baseUrl）** | 例如 `https://api.deepseek.com/v1`；也支持本机 `http://127.0.0.1:8199/v1`（用 `llama-server` 当 OpenAI 兼容端点） |
| **API Key** | 只写入 `<项目根>\data\settings.json`（已 gitignore），**不进日志、不进交付文档**；页面用密码框，不回显 |
| **模型名** | 服务端要求的模型 id，例如 `deepseek-chat` |
| **温度 / 单次上限** | 采样温度与单次回答 token 上限 |

- **连通性自检**：点「**测试连接**」（`POST /app/llm/api/test`）—— 先试 `/models`（多数服务支持），再发一条极短对话（`max_tokens: 8`，非流式），返回毫秒耗时与模型名；失败时给出状态码与原因。
- **对话**：走 `/chat/completions` **流式**，转成本程序的前端 SSE。**只做纯聊天**：一段系统提示词（仍是 `assets/templates/anima-system-prompt.txt` 的**原文**）+ 最近 N 条对话，**不挂工具、不挂检索、不挂推理内核**。
- **常见错误映射**：`401/403` → API Key 无效或没权限；`404` → baseUrl 或模型名不对（多数服务要写到 `/v1` 这一层）；`429` → 触发限流。
- 外接路径同样会做输出规范化与**角色 tag 补全**，返回帧里带 `provider: "api"`；本地路径带 `provider: "local"`。

这两项在**插件版**里存在，本独立版**有意不提供**。原因写在设置页的「窗口」卡片里：

> 独立版是纯浏览器页面（后端进程 + 静态页面），**没有托盘进程**，因此「启动后自动最小化到托盘」与「关闭按钮行为」这两项不适用，故不提供。要退出请关闭启动器窗口或在窗口里按 `Ctrl+C`。

**注意区分两个「托盘」**：上面说的是**浏览器页面侧**（页面本身无法管窗口，所以不提供假开关）；而**启动器侧**（`scripts\start.ps1`）现在确实会拉起一个独立进程的**系统托盘图标**并最小化控制台 —— 那是启动器行为，用 `-NoTray` 关闭，与设置页无关，见 §4.1 与 `FEATURES.md` 的 F6。

### 9.2 局域网访问

打开「允许局域网访问」后，后端改为监听 `0.0.0.0`，并自动生成一个**令牌**（显示在设置页）。局域网内其它设备必须带上令牌才能访问：

```
http://<本机IP>:8788/?token=<令牌>
```

或带 `X-DCP-Token` 请求头。启动日志里的"局域网地址"行已经带好令牌，直接用即可。**关闭令牌 / 未开启局域网时不做校验。**

> **本机不受令牌影响（v1.1.0 修复）**：令牌是给**局域网内其它设备**的，来自回环地址（本机浏览器 / 启动器探活）的请求一律放行。
> 这一点很关键：旧实现对所有来源都要令牌，于是开启局域网后**本机页面自己的接口也全部 401** ——
> 设置页会被外壳换成"后端 API 不可用"，令牌反而永远看不到；而且启动器 `scripts\start.ps1` 用
> `http://127.0.0.1:<端口>/app/state` 探活、不带令牌，一旦局域网开关被保存过，**下次双击 `start.cmd` 会等满 60 秒后报"后端在 60 秒内没有就绪"并杀掉后端**。
> 现在：保存后令牌会立刻显示在设置页（无需刷新页面），本机照常使用；其它设备仍然必须带 `?token=`（或 `X-DCP-Token`）。

## 11. 常见问题（FAQ）

### 1) 网页打不开 / 后端没起来

- 确认是通过 `start.cmd` 或 `pwsh -File .\scripts\start.ps1` 启动的，并**使用启动日志里给出的地址**（端口被占用时后端会自动往后试，实际端口可能不是 8788）。
- 启动器会打印"后端在 60 秒内没有就绪"并附带最后几行输出；也可以看 `<项目根>\logs\server-console.out.log` 与 `logs\server-console.err.log`。
- 首次运行需要联网下载便携 Node；没网且没装 Node 18+ 会失败，可按 `scripts\bootstrap.ps1` 的提示手动把 `node.exe` 放到 `runtime\node\`。
- 用 `-Foreground` 可以在控制台直接看到后端日志。

### 2) 显示 "ComfyUI 离线"

- 点面板上的「**启动 ComfyUI**」按钮，等它就绪（最多 180 秒，面板会轮询 `/system_stats`；冷启动较慢，日志在 `logs/comfyui.log`）。
- 外接模式先确认「设置 → ComfyUI」里的目录正确，点「检测」看布局与 `main.py`、`python` 是否都找到了。
- 仍失败就看 `<项目根>\logs\comfyui.log`（面板/向导里也能看）。

### 3) 模型下拉是空的

- ComfyUI 必须**已经装好并启动**，面板才会去问它的节点列表；离线时下拉为空是正常的。
- 确认权重已下载到 ComfyUI 的 `models\diffusion_models\`（以及 `text_encoders\`、`vae\`）。用「设置 → 自检」或向导的模型列表看"已安装"标记。
- 自检里的 `comfy-embedded-missing` 提示表示内嵌模式还没装本体，回向导跑一遍。

### 4) 生成时 `VAEDecode` 报通道数错误

这是**扩散模型的潜空间通道数与 VAE 不匹配**（本机实测 Anima 系是 16 通道，Qwen-Image 2.1 是 64 通道）。面板会在原始报错后追加一段人话提示。

**处理**：换成同一管线配套的 VAE（Anima 系 → `qwen_image_vae.safetensors`；Qwen-Image 2.1 → `qwen_image_2.1_vae_bf16.safetensors`）。正常情况下面板的**提交前闸门**会先一步拦住这种组合并点名两个文件。

### 5) 报 `normalized_shape=[4096]` / 编码器选错

这是**文本编码器选错了**：`[4096]` 是 Qwen-Image 2.1 文本投影要求的维度，而实际送进去的是 1024 维。

**处理**：
- Anima 3.8B / Anima 通用 → 「原生编码器」选 **`qwen_3_06b_base.safetensors`**（1024 维）；
- Qwen-Image 2.1 → 「文本编码器」选 **`qwen3vl_8b_w4a8.safetensors`**（4096 维）。

### 6) 点了"启动"没反应

- 看 `<项目根>\logs\comfyui.log` 的尾部 —— 面板与向导里都有日志查看入口。
- 若日志里是"未找到可用的 Python 解释器"，说明内嵌模式缺 `python_embeded`：回向导用「便携版」重装一次（或「已有目录」导入时会一并把 `python_embeded` 带过来）。
- 若 ComfyUI 其实已经在跑（但你不是通过面板启动的），「停止」会尝试结束监听该端口的进程。

### 7) 下载很慢 / 一直失败

- 程序会自动切镜像并**明确提示**切到了哪个源。第七轮起判定规则是两条，都很直观：
  - **10 秒内没有正常开始下载**（连接已建立但收到的数据不足 64 KiB）→ 立刻换下一个源；
  - **连续 15 秒没有收到任何新字节**（下载中途卡死）→ 立刻换下一个源；
  - 另外保留一条"持续慢"的竞争规则：前几个候选只要**整个窗口（默认 30 s）均速低于 200 KB/s** 也会换源，最后一个候选不按"慢"掐（只看停滞），避免所有源都慢时把能下完的文件掐掉。
  - **这些阈值都能在「设置 → 下载源」里调**（开始下载期限 / 中断判定 / 慢速阈值 / 慢速窗口 / 停滞阈值）。
- **不确定哪个源能用？先测速**：「设置 → 下载源 → 镜像测速」，粘贴任意直链（默认就是最小档主权重），选 100 MiB，点「开始测速」——它会用真实下载路径把**每个候选来源各下一段**，列出首字节耗时、实际速度与判定。测速不落盘。
- 各组件默认梯队（第七轮实测）：
  | 组件 | 默认来源顺序 |
  |---|---|
  | 模型权重（HuggingFace 系） | ModelScope（`resolve/master`）→ aifasthub → hf-api.gitee.com → ai.gitcode.com → hf-mirror |
  | Node 便携运行时 | 清华 TUNA → 官方 nodejs.org → 华为云 → cdn.npmmirror → registry.npmmirror |
  | 角色词表 `danbooru.csv` | jsDelivr（fastly / gcore）→ raw.githubusercontent → gh-proxy / ghfast |
  | GitHub Release（ComfyUI 便携包 / llama.cpp / 7-Zip） | gh-proxy.com → **down.npee.cn**（`?<原链接>` 形式）→ ghproxy.net → ghfast.top |
  | 7-Zip | GitHub `ip7z/7zip`（经 gh-proxy，实测 1.8 MB/s）→ 官方 7-zip.org（实测只有 17–25 KB/s）→ 系统已装 7-Zip |
  | pip（git 模式装依赖） | 清华 PyPI → 阿里云 PyPI |
- 下载支持断点续传重试；连续失败会把**每个来源的失败原因**列出来，不会只说一句"失败了"。
- 实在慢可以手动下载，然后：ComfyUI 本体用向导的「压缩包」指定本地 `.7z`；模型装到本机已有 ComfyUI 目录后用向导硬链接导入（设置「从本机已有模型目录导入」）。
- **GitHub 系资源的现实情况（如实说明）**：2026-09 在本机实测了 20+ 个 GitHub 代理，**只有两个是快源** —— `gh-proxy.com`（230 MB/15 s ≈ 15 MB/s）与 `down.npee.cn`（`?<原链接>` 形式，4.07–24.92 MB/s，官方 v0.37.0 资产 4/4 通过）；`ghproxy.net` / `ghfast.top` 能出数据但被限速到 0.10–0.37 MB/s；`ghps.cc` 全站 404；其余 DNS 失效/证书过期/403/429。ComfyUI 便携包与 llama.cpp 的程序里另备了多条后备路径（哈希校验通过的官方旧版镜像、hf-mirror 上的第三方构建、git clone 模式、本地归档、外接已有目录）。

### 8) 局域网访问提示需要令牌

打开「允许局域网访问」后必须带令牌：

```
http://<本机IP>:8788/?token=<令牌>
```

令牌在「设置 → 监听地址」里显示，启动日志的"局域网地址"行也已带好。

### 9) 本地 LLM 启动失败 / 显存不足

- 先看 `<项目根>\logs\llama-server.log`。程序会先试 CUDA 版，失败自动回落 CPU 版重试；两级都失败会给明确文案。
- **显存不足**：在「本地 LLM → 安装运行时」点 **CPU 版**重新安装；或换更小的 GGUF。
- 若报 CUDA 运行库缺失，CUDA 版安装流程会自动补下 cudart 包；仍失败就退回 CPU 版。

### 10) 换了电脑 / 换了盘符，外接模式失效

外接模式记录的是**绝对路径**，所以拷贝到别的机器后可能指不到。启动时「自检」会报：

> 外接 ComfyUI 目录不存在（多半是整体拷贝到别的电脑/盘符后路径失效）

**处理**：打开「设置 → ComfyUI」重新指向本机的 ComfyUI 目录，或改用「内置模式」由向导安装。**其余数据（设置、收藏、黑名单、LLM 会话）都随项目文件夹走，不受影响。**

### 11) 启动后页面提示"请先完成向导"

向导记录（`data\setup.json`）还没有 `completed`。可以直接点横幅上的「向导」按钮跑一遍；如果你只想用外接模式，向导第 1 步选「外接模式」+ 填目录 + 检测通过后跑完即可（模型可一个都不勾，稍后在生图栏按需下载）。

### 12) 生图慢 / 显存爆了（OOM）

8 GB 显存下大批量（例如 20 张 1024²）容易 OOM。**处理**：降低张数或分辨率；点「释放显存」清掉缓存；Anima 系可换 `Anima-2.9B-preview-v1_int8_convrot.safetensors` 这类 int8 量化档。

### 13) 想用手机 / 局域网访问

打开「设置 → 监听地址 → **允许局域网访问**」并保存：后端改为监听 `0.0.0.0`，并自动生成一个**令牌**。然后在手机/别的电脑的浏览器里打开：

```
http://<本机IP>:8788/?token=<令牌>
```

- 令牌在「设置 → 监听地址」里显示，启动日志的"局域网地址"行也**已经带好令牌**，直接照抄即可；
- 两端要在**同一个局域网**（同一 Wi-Fi/网段），且 Windows 防火墙首次会弹询问，需要**允许**该程序访问专用网络；
- 手机浏览器打不开时优先检查：防火墙拦截、IP 变了（DHCP）、以及地址里有没有漏掉 `?token=`。

### 14) 8 GB 显存想跑推荐目录里的 9B，跑得动吗

推荐目录里的 9B 是 `Qwen3.5-9B-UD-Q4_K_XL`（**5,966,095,584 B ≈ 5.56 GiB** 权重）。8 GB 显存**装得下权重但 KV 缓存余量很小**，建议按顺序试：

1. 先**关掉 ComfyUI 释放显存**（生图和本地 LLM 抢显存是 8 GB 机器最常见的失败原因）；
2. 在 `data\settings.json` 里把 `llm.gpuLayers`（`-ngl`）调小（例如 20），或设 0 走纯 CPU；
3. 换更省的档：`Qwen3.5-9B-Q4_K_M`（5,680,522,464 B）或 `Qwen3-8B-Q4_K_M`（5,027,784,512 B）；
4. 仍不行就在「本地 LLM → 安装运行时」点 **CPU 版**。

> **如实说明**：本版只做到「目录登记 + 一键下载可用」，**9B 的下载完成与加载运行验证尚未完成**（见 `docs/FULL-REFERENCE.md` 的「附：第二轮改动实测」H）。

### 15) 外接 API 报 401 / 404 怎么办

- **401 / 403**：API Key 无效或没有权限 —— 在「设置 → 本地 LLM」重新粘贴 Key（页面用密码框、不回显；Key 只写在 `<项目根>\data\settings.json`，已 gitignore，不进日志）。
- **404**：`baseUrl` 或模型名不对。绝大多数服务要写到 `/v1` 这一层，例如 `https://api.deepseek.com/v1`；用本机 `llama-server` 当端点时是 `http://127.0.0.1:8199/v1`。
- **429**：触发限流，稍后再试。
- 先用设置页的「**测试连接**」自检：它先试 `/models`，再发一条极短对话；返回里带状态码、耗时与错误正文，照着改即可。

### 16) 角色名识别不准（例如「蕾姆」没被翻成规范角色 tag）

**先说结论**：8 GB 显存能跑的文生文模型**都不能可靠地**做这件事 —— 唯一的 NL→Danbooru 模型（BooruNL-0.8B）模型卡明确写"不输出角色/画师 tag"；唯一的 Danbooru tag 模型（DanTagGen）是 tag 进 tag 出；明确用 DanbooruTags 微调的权重是 **27B**，最小量化也放不进 8 GB。本版因此用「**更大的通用模型 + 确定性角色词表兜底 + 中文别名**」。可操作的做法：

1. **加一条中文别名（最有效）**：在「工作台 → 本地 LLM → 角色词表」卡片里填「中文/日文名 → 对应 Danbooru tag 名」并保存，写入 `<项目根>\data\character-aliases.json`（用户别名会覆盖内置同名项）。
2. **换更大的模型**：在「推荐模型」里点「下载」9B 并「设为默认」；把**词表 + 更大模型**一起用效果最好。
3. **确认词表已装**：点「下载/更新词表」（约 3.5 MB）；卡片会显示「词表就绪 / 角色条目 40,931」。
4. **看补全是否发生**：界面上会出现一条系统提示「**已按角色词表补全角色 tag：…**」——是显式告知，不是静默改内容；没有这条提示就说明这次没解析出角色名。
5. 也可以直接搜：在「搜角色（中英均可）」里输入名字，结果行点 **📋 复制** 拿到规范 tag，再手填进提示词。

### 17) 托盘图标不见了

- 先看 `<项目根>\logs\tray.log`：里面有「托盘已就绪：Url=… BackendPid=…」或「后端已退出，托盘关闭」，加载 WinForms 失败也会记一条原因。
- **后端退出后图标自动消失是设计行为**（避免留下点不动的幽灵图标）；重新启动项目即可。
- Windows 11 默认把托盘图标收进「隐藏的图标」区域，点任务栏的 `^` 展开就能看到，也可以拖出来固定。
- 启动时带了 **`-NoTray`** 或 **`-Foreground`** 就**不会**有托盘图标（这是有意的）。
- 如果 `scripts\tray.ps1` 缺失或 WinForms 不可用，启动器会打一条**警告并保持控制台可见**，此时按 `Ctrl+C` 退出。

### 18) 下载一直失败怎么办

1. 打开「设置 → 下载源」，点 **「一键填入国内优选源」**：一次把 HuggingFace 镜像设成 `hf-mirror.com`、打开 ModelScope、补齐四个 GitHub 代理（`gh-proxy.com` / `ghproxy.net` / `ghfast.top` / `ghps.cc`）、把停滞阈值设为 30 KB/s。
2. 看任务日志**开头那一行**：「`<文件名> 候选来源 N 个：官方源 → hf-mirror → modelscope → …`」—— 就知道程序到底试了哪些源；失败时结尾会逐条列出「`来源#轮次: 原因`」。
3. **ModelScope 不是每个文件都有**：`installer/llm-models.json` 的 `modelscope` 字段标了有没有；仓库不存在时它会立刻 404，自动跳到下一个候选。
4. 慢速判定是**窗口均速**而不是瞬时值，而且**最后一个候选只按停滞阈值判**（只要还在动就会把它下完）—— 避免"所有源都慢"时把本来能下完的文件掐掉。
5. 请求一律带 `User-Agent` 与 `Range` 头（顺带支持断点续传）；连上后 20–60 秒一个字节都没动才判死换源。
6. 实在下不动就手动下载：ComfyUI 本体用向导的「压缩包」/「已有目录」，模型用「添加本地路径」或向导的「本地已有 ComfyUI 目录」。

### 19) 9B 模型一直下不完，是不是坏了

不是。9B 权重是 **5.56 GiB** 量级的单文件，在国内网络下**中途掉线是常态**（本机实测本轮多次中断：官方源超时、镜像窗口均速只有 1–2 MB/s）。程序已经：① 候选来源逐个试、② 每源重试 2 轮、③ 断点续传（`.part` + `Range`）、④ 失败时如实列出每个源的原因。**它会明确报错，不会静默失败**；重跑同一任务会从断点继续。也可以用「一键填入国内优选源」后重试，或手动下载再「添加本地路径」。
